# FE 서버 선택·브라우저 인증 회귀 검증

리뷰 후속 수정은 같은 계정·적격 서버의 편집 초안을 재확인 뒤에도 보존하고, 인증 취소 화면에서 정상 복귀하며, 예약 JWT 갱신과 401 복구를 하나의 진행 중인 요청으로 공유합니다. 확인 중이거나 확인 불가인 서버 화면은 숨기고 조작·데이터 요청을 차단합니다. 계정·서버 접근 범위가 바뀌면 이전 편집 상태와 늦은 응답을 정리합니다.

## 실제 FE→BE 브라우저 테스트

저장소 루트의 Herdr `verify` 탭에서 실행합니다.

```bash
npm run test:e2e -- tests/e2e/frontend-selection.test.ts
```

이 테스트는 실제 App 화면과 Axios, Vite 프록시, 실제 BE HTTP 서버, 격리된 SQLite 저장소를 연결합니다. 인증·서버 목록·토큰·데이터 API의 응답을 별도 fixture로 대체하지 않습니다. 외부 Discord 인증·가입·설치·채널 관측만 테스트 어댑터로 제어하고, 서버 변경 이벤트는 BE의 실제 인증된 이벤트 수신 경로로 전달합니다.

- OAuth state 발급과 로그인, HttpOnly 쿠키 복원, 일반 멤버·설치된 가입 서버 필터, 카드·모니터링 채널이 없는 서버 표시
- 정상 빈 목록과 설치 확인 불가 구분, 초안 보존과 차단·복구, 봇 제거·재설치·사용자 탈퇴 후 선택·데이터 인가
- 실제 Decision Record 편집 초안 보존과 OAuth 계정 전환 후 이전 카드 접근 거부
- 인증 취소 후 로그인 화면 복귀와 유효한 기존 쿠키 세션 복원
- 실제 JWT 경로에서 예약 갱신 요청을 잠시 지연시키고 만료된 조회 3개를 겹쳐 갱신 1회·조회별 재시도 1회를 확인합니다. 이어 변경 요청 중복 방지와 JWT 갱신에 따른 서버 목록 재조회 방지를 확인합니다. 전송 시점만 제어하며 BE 응답 내용은 대체하지 않습니다.

Chrome/Chromium이 필요합니다. 실행 파일 경로는 `CHROME_EXECUTABLE`로 지정할 수 있으며, 미지정 시 macOS Chrome과 일반적인 Linux Chrome/Chromium 경로를 탐색합니다. 브라우저가 없는 환경에서는 이 네 시나리오가 명시적으로 skipped 처리되므로 전체 연동 검증을 완료했다고 보고하면 안 됩니다. 브라우저가 설치된 환경에서 네 테스트가 모두 실행·통과했는지 확인합니다.

## FE 전용 화면·HTTP 경합 회귀

```bash
npm run test --workspace=apps/frontend-main
```

실제 화면의 입력·채널 체크·취소 버튼과 HTTP 경계를 검증합니다. 지연된 외부 응답으로 예약 갱신과 401 복구를 겹치게 해 요청 공유, 일시 장애, 계정 전환, 로그아웃 경합을 확인합니다. 이 빠른 회귀의 BE 대체 응답은 위 실제 BE 연동 검증을 대신하지 않습니다.

브라우저 테스트 파일은 순서대로 실행합니다. 여러 Vite 서버가 같은 FE 의존성 캐시를 동시에 재생성하면 화면 로딩이 멈출 수 있어 테스트 명령에 `--test-concurrency=1`을 지정했습니다.

## 전체 확인

```bash
npm run typecheck
npm test
```

테스트는 임시 DB·브라우저 프로필·동적 로컬 포트를 사용하고 종료 시 정리합니다. 실제 Discord 서버의 설치·탈퇴 조작이나 운영 DB 변경은 수행하지 않으며, 개인 인증 정보는 사용·출력하지 않습니다. 외부 관측을 제어한 자동 검증과 실제 Discord 수동 검증 결과를 구분해 기록합니다.

FE 변경은 기존 작업 브랜치와 한글 PR로 제출합니다. 부모 저장소는 검증한 FE 커밋을 명시적으로 기록하고, PR 병합 대기 커밋을 사용할 경우 그 상태를 알립니다.
