# 손상된 분석과 실패 세션의 동기화 진행

상태: 승인됨, 구현 전

## 배경과 결정

유효하지 않은 관계 하나 때문에 독립적인 후속 Scan Range까지 정지하지 않도록, 세션별 손상·실패를 영속적으로 기록하고 복구 가능한 실패 구간을 건너뛴 뒤 동기화를 진행한다. 이는 부분 결과의 가용성과 관계 누락을 확인할 수 있는 추적성 사이의 선택이다. 이 결정은 실패 구간 앞에서 checkpoint를 유지하던 ADR-0020과 ADR-0023의 규칙을 아래 범위에서 변경하며, ADR-0018의 실패를 정상 분석으로 간주하지 않는 원칙은 유지한다.

- Extract는 Zod 기반 JSON Schema로 필수 필드, 타입, enum과 카테고리를 제한한다. 서버는 참조 대상 존재와 관계별 노드 타입을 계속 검증한다.
  NVIDIA에서 Extract의 `json_schema`를 지원하지 않는 엔드포인트는 `NVIDIA_EXTRACT_JSON_SCHEMA=false`로 JSON 객체 모드를 선택한다. 이 모드에서도 스키마를 프롬프트에 제공하고 서버에서 결과를 검증한다.
- 존재하지 않는 노드를 참조하거나 허용되지 않은 노드 타입을 연결한 관계는 제거한다. 관계 ID·타입·양끝 노드 ID와 확인 가능한 타입·사유·Analysis Request 및 세션 ID를 영속적으로 남긴다. 없는 Rationale, Action Item, 합의나 관계는 만들지 않는다.
- 제거로 Rationale 또는 Action Item이 고립되면 노드를 버리지 않고 Repair한다. 연결된 Rationale이 없어지면 그 사실을 반영하고 Verify로 원문에 근거가 누락됐는지 확인한다.
- 남은 그래프가 구조 검증과 의미 Verify를 통과하면 세션의 모든 Decision Candidate를 Review Queue에 발행하며 관계 손상 경고를 표시한다. 성공한 결과에 경고와 손상 이력을 함께 보존한다.
- 세션에 국한된 구조·의미 검증 실패는 후보를 발행하지 않고 해당 세션을 **분석 실패로 건너뜀**으로 영속화한다. 정상 분석의 결정 없음과 구별하고 원래 Scan Range, 실패 세션의 메시지 ID와 실패 사유를 남긴다. 실패 기록과 진행 상태는 checkpoint 전진보다 먼저 또는 같은 트랜잭션에서 확정해 누락 없이 복구한다.
- **출력 형식 실패**, AI 호출 타임아웃, 세션 시간 예산과 논리 호출 예산의 소진도 세션에 국한된 실패로 보고 **분석 실패로 건너뜀**으로 기록한다. 워크플로 안에서 같은 단계를 즉시 다시 호출하지 않으며, ADR-0025의 숨은 재시도 금지와 세션당 논리 호출 상한(5회)을 유지한다. 세션 시간 예산은 논리 호출 상한 × 호출 제한 시간에 맞춰 100초(5회 × 20초)로 둔다.
- 타임아웃 한 건, 키 하나의 `429`·인증 실패, 소유권 상실로는 Analysis Queue 전체를 멈추지 않는다. 키 단위 실패는 다른 키로 다시 시도한다. 큐 전체 일시 중단은 provider 전체 장애를 뜻하는 `5xx`와, 쓸 수 있는 키가 모두 인증·권한 실패인 인증 장애, DB 장애에만 적용한다. 남은 키가 모두 `403`으로 쉬는 중이면 대기가 아니라 인증 장애로 알린다.
- 출력 상한에서 잘린 응답은 같은 입력과 상한으로 다시 보내도 같은 결과가 나오므로 자동 재시도하지 않고, 사유를 출력 상한 초과로 남긴 채 수동 재분석만 허용한다. 자동 재시도 중에 잘려도 같으며, 복구 기록은 가장 최근 실패의 종류를 보존한다. 빈 응답과 해석할 수 없는 응답, 형식을 어긴 Verify 응답은 자동 재시도 대상이다.
- 자동 재시도는 시도 번호에 따라 seed를 바꿔 같은 출력이 반복되지 않게 하며, 같은 시도 번호는 같은 seed로 재현한다. 최초 분석은 provider 기본 seed를 쓰고, 재시도는 기본 seed에 시도 번호(1부터)를 더한다.
- 요청이나 AI 호출 슬롯의 소유권을 잃어 중단된 호출은 분석 실패가 아니다. 세션을 건너뜀으로 기록하지 않고 재시도 횟수에도 넣지 않는다.
- 동기화는 실패 세션의 재시도를 기다리지 않고 진행한다. 자동 재시도는 최대 두 번이며 최초 실패 후 1분, 첫 재시도 실패 후 5분을 기다린다. `429`는 Retry-After와 키별 제한을 지킨다. 인증 오류처럼 설정 변경이 필요한 오류는 자동 재시도하지 않는다. 전체 분석에 영향을 주는 인증·DB 장애는 동기화를 일시 중단하고 원인을 표시한다.
- 자동 재시도와 수동 재분석이 같은 세션에서 동시에 실행되지 않도록 소유권을 보장한다. 성공 시 기존 중복 판별을 적용해 후보를 발행하고 실패 상태를 복구됨으로 변경한다. 확정·수정된 사람의 결과를 덮어쓰지 않는다. 손상 경고는 복구 시 해제하되 과거 이력은 보존한다.
- 재분석은 최초 Analysis Request의 동일 Discussion Context를 사용한다. 실패한 입력의 보관 기한은 최초 요청 생성 시점부터 30일이며 재시도로 연장하지 않는다. 만료 후 원래 입력으로는 재분석할 수 없음을 표시한다. 사용자가 현재 Discord 메시지의 분석을 별도로 요청하면 새 Analysis Request를 만든다. 다른 기록이 필요로 하는 증거와 원문을 삭제할 때는 기존 보존 계약을 함께 지킨다.
- Review Queue는 손상 후보의 경고를 표시한다. 동기화 상세는 완료 상태와 함께 손상·건너뜀 건수, 세션 사유 및 재시도 상태를 보여준다.

이 문서는 합의된 목표 동작이다. 배포된 코드가 이미 이 동작을 제공한다는 뜻은 아니다.
