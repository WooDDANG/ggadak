# Explicit provider HTTP for bounded analysis

The durable Agentic workflow needs an instance-specific transport, a cancellable deadline, one visible generation request per attempt, and raw results for a bounded repair. The installed legacy OpenAI SDK adapter does not expose an instance-specific fetch boundary; relying on SDK retries also makes persisted attempt budgets harder to audit.

For BE decision analysis we support native Gemini/OpenAI HTTP and Antigravity `agy` subprocess transport inside the existing provider-agnostic AI Adapter. AGY is the current default selected by the user. Zod remains the schema authority: the Adapter sends JSON Schema, handles provider errors and usage, and the workflow validates structure and meaning before publication. This supersedes the BE transport choice in [ADR-0006](0006-vercel-ai-sdk-and-zod-structured-outputs.md) and [ADR-0014](0014-multi-decision-llm-extraction-engine.md); it does not change the Service/Adapter boundary.

We accept responsibility for maintaining provider request/response contracts and verify them with injected HTTP fixtures and independent CLI fixture processes. Adding another provider requires an explicit Adapter implementation; no implicit SDK retry or global fetch replacement is used. Real provider connectivity and model quality remain separate opt-in evaluations.

Gemini generation attempts explicitly preflight the full request with countTokens and fetch model input/output limits once per Adapter/model. These requests share the attempt's cancellation signal and deadline; they do not add generation attempts or hidden retries. Evaluation HTTP budgets count all preflight and generation requests, while prospective countTokens values are excluded from consumed generation-token usage. The current Gemini 3.8 integration uses separate input/output capacities; a switch to a shared-context model family requires its combined-window policy to be verified. See [token limits research](../research/gemini-token-limits-2026-10-15.md).

AGY attempts run one fresh CLI session using the BE OS user's cached login. An isolated temporary workspace contains a result-only agent with `finish` as its sole tool; prompts go over stdin and schemas use temporary files. The child receives an explicit environment allowlist without application credentials. Canceling or closing the session terminates its process group before temporary-file cleanup. A failed CLI attempt never falls back to an HTTP provider. CLI-internal model turns are controlled by the CLI harness, so the one-request statement applies to HTTP generation; an AGY logical attempt is one bounded process session, with its aggregate usage recorded.

AGY does not expose HTTP countTokens or maxOutputTokens controls. An explicitly configured input-token preflight cap is rejected in CLI mode; character safeguards still work. Application output-token caps are checked against returned usage after generation, not enforced at the provider beforehand. CLI quotas, cached credentials, and model/context behavior belong to Antigravity and are not assumed equal to Gemini API quotas. The existing HTTP evaluation runner remains HTTP-specific. See [CLI research and verification](../research/agy-cli-integration.md).
