# 이벤트 관측과 요청 제한 시 서버 권한 확인

Status: accepted (Q1–Q8 합의 후 to-tickets·implement 요청으로 구현 승인)

멤버 이벤트 수신을 정상 운영 기준으로 삼고 Discord Portal과 Bot 설정을 모두 맞추며, 비활성화나 연결 신뢰 상실을 운영 상태에 명시한다. Discord 요청 제한 시 유효한 로그인과 편집 초안은 유지하지만, 확인되지 않은 권한으로 데이터 조회·수정을 허용하지 않는다. Discord가 제공한 재시도 대기 시간을 준수하고, 대기 종료 자체로 재조회를 시작하지 않으며 이후 사용자 재시도나 실제 접근에서 필요한 확인을 수행한다.

서버 선택 목록의 신뢰는 설치된 서버의 기존 사용자 가입 증명과 이벤트 연속성을 기준으로 판단한다. 봇 미설치 membership이 있다는 이유만으로 설치 서버 선택 목록 전체를 재검증하지 않으며, 가입·설치 변경이나 관측 공백에서는 필요한 확인을 수행한다. 봇 설치나 이벤트만으로 새 사용자 가입 권한을 부여하지 않는다.

요청 제한 대기는 같은 사용자의 여러 탭·브라우저 세션에 공유해 자격증명 회전이나 별도 세션 요청이 대기를 우회하지 않게 한다. 사용자별 제한은 다른 사용자로 확장하지 않으며, Discord가 명시한 전체 제한은 제공된 적용 범위에 맞춰 처리한다. 대기 중에는 추가 외부 호출 없이 남은 시간을 안내한다.

이벤트 관측을 신뢰할 수 없더라도 실제 요청에서 새 Discord 가입·권한 검증에 성공하면 그 요청을 허용한다. 실패·요청 제한 대기 중에는 데이터를 보류하며 과거 권한을 일정 시간 무조건 재사용하지 않는다. 이 결정은 고정 주기 전체 권한 재조회 제거 방침을 유지하고, 봇 미설치 서버의 기존 기록 접근 정책도 보존한다.

권한 확인 대기 중에는 로그인 계정명과 로그인 상태를 계속 표시하고 서버 데이터 영역과 초안 제출만 차단한다. 편집 초안은 보존한다. 로그인 실패·봇 미설치와 구분해 서버 권한 확인 대기 및 남은 시간을 안내한다.

요청 제한의 적용 범위와 대기 종료 시각은 BE 재시작 후에도 보존하며, 재로그인이나 자격증명 회전으로 우회하지 않는다. 이는 권한 조회 결과의 시간 기반 재사용이 아니라 외부 재요청을 허용할 시각의 보존이다. Discord가 제공한 유효한 대기 시간을 우선하며, 429에 해당 값이 없거나 해석할 수 없을 때만 기본 30초를 적용한다. 대기 종료는 자동 요청을 발생시키지 않는다.
