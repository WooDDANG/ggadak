# NVIDIA 다중 계정 키 운영

BE는 `NVIDIA_API_KEY_1`부터 `NVIDIA_API_KEY_4`까지 설정된 키를 Extract·Verify·Repair의 AI Call에 순환 배정한다. 번호 키가 하나라도 있으면 `NVIDIA_API_KEY` 대신 번호 키만 사용한다. 앞뒤 공백과 빈 값은 제거하고 같은 키는 한 번만 포함한다. 번호 키가 없으면 기존 단일 키를 사용한다. 키가 하나도 없으면 NVIDIA Provider 설정 오류를 반환한다. AGY는 이 예산을 사용하지 않는다.

루트 `.env` 또는 배포 환경의 secrets에 키를 설정하고 BE를 재시작한다. 배포에서도 네 변수를 모두 등록해야 한다. 로컬 `.env`의 키는 자동으로 배포 환경에 전송되지 않는다. 키의 인증 유효성은 실제 요청 결과로 확인하며, 단순 설정 확인은 인증 성공을 의미하지 않는다.

## 호출 예산과 동시성

`NVIDIA_REQUESTS_PER_MINUTE`는 계정당 호출 예산이며 기본값은 40이다. 이는 기존 운영 명세의 기준이며 NVIDIA 전체 계정에 대한 일반 보장값이 아니다. 실제 계정 한도 이하의 양의 정수로 설정한다. 모든 BE 인스턴스에 같은 값과 같은 키 집합을 설정해야 한다.

최근 60초 동안의 예약 횟수가 한도보다 적고 다른 호출이 사용 중이 아닌 키를 선택한다. 각 키는 한 번에 하나의 AI Call에만 배정한다. 모든 키가 바쁘면 Analysis Queue가 대기하고, 호출 예산이 소진되면 가장 오래된 예약이 60초를 벗어난 뒤 재시도한다. 네 키가 독립적인 계정 한도를 가진 경우 사용 가능한 키를 고르게 선택한다. 여러 키가 같은 계정에 속해 한도를 공유하는지는 자동 판별하지 않는다. `AI_CALL_CONCURRENCY`, `AI_SESSION_CONCURRENCY`, `ANALYSIS_CONCURRENCY`는 별도의 동시성 설정이며, 동시 호출을 늘리려면 함께 조정해야 한다.

모든 BE 프로세스가 같은 SQLite 저장소를 공유해야 한다. 계정 식별자는 키의 SHA-256이며 키 원문은 저장하지 않는다. 키 잠금과 호출 예산은 하나의 트랜잭션에서 확정한다. 요청 중 잠금을 주기적으로 갱신하고, 프로세스가 종료되면 만료 후 다른 요청이 사용한다. 재시작해도 최근 호출 기록, cooldown과 인증 실패 상태가 유지된다. 서로 다른 DB를 사용하는 배포 사이에는 예산이 공유되지 않는다.

이번 변경에는 추가 테이블 migration이 포함된다. 기존 DB를 백업하고 저장소의 DB 업그레이드 절차를 수행한 뒤 새 BE를 실행한다. 이 기능의 자동 테스트는 임시 DB에만 migration을 적용한다.

이전 버전의 최근 호출 기록은 정확하게 복원할 수 없으므로 migration 직전 사용된 키는 안전을 위해 최대 약 1분 대기한다. 모든 BE 프로세스를 같은 버전으로 전환한 뒤 호출을 재개한다. 이전 버전과 새 버전의 혼합 실행은 키 잠금과 호출 기록을 공유하지 않으므로 지원하지 않는다.

## 오류와 재개

- 429는 해당 키에만 `Retry-After`의 초 또는 HTTP 날짜만큼 cooldown을 적용한다. 헤더가 없거나 잘못되면 60초를 적용한다.
- 401/403은 해당 키를 사용 대상에서 제외한다. 해당 요청은 기존 Analysis Queue의 제한된 재시도 경로에서 다른 키를 사용할 수 있다. 모든 키가 인증 실패면 명확한 인증 오류로 종료한다.
- 키를 교체하면 새 식별자로 인식해 다시 사용한다. 인증 실패했던 같은 키는 서버 재시작만으로 복구되지 않는다.
- 모든 사용 가능 키가 대기 중이면 Analysis Queue에 다음 가능 시점을 전달한다. 이 대기는 AI Call 시도 수, 논리 호출 수와 세션 실행 시간 예산을 소비하지 않는다. 재개할 때 완료한 분석 단계는 반복하지 않는다.
- SDK 자동 재시도는 꺼져 있다. 하나의 AI Call은 네트워크 생성 요청을 한 번만 수행한다.

`BE-NVIDIA` 로그의 `nvidia.key.selected`, `nvidia.key.completed`, `nvidia.key.failed` 이벤트에서 환경변수 이름(`keyName`)과 HTTP 상태를 확인한다. 키 풀 대기는 `nvidia.key.waiting`에 기록한다. 로그에 키 원문이나 Authorization 헤더를 추가하지 않는다.
