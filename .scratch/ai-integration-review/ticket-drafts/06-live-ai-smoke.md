# 06: 실제 AI 연결을 별도 실행으로 확인하기

**What to build:** 일반 테스트와 분리된 명시적 실행으로 지정한 공급자·모델·키가 실제 분석 요청을 처리하고 후보를 임시 DB에 저장할 수 있는지 확인한다.

**Blocked by:** 03: 공급자 오류에 맞는 재시도와 retained failure 처리; 04: Gemini에 분석 응답 계약을 전달하기.

**Status:** needs-triage

- [ ] 일반 테스트 명령에는 실제 AI 호출이 포함되지 않는다. 연결 검증은 공급자·모델·호출 수 상한을 명시해 실행한다.
- [ ] 코드에 키를 넣거나 출력하지 않고 기존 환경에서 읽는다. 공급자와 모델은 명시적으로 지정하고 mock/fallback 성공을 연결 성공으로 인정하지 않는다.
- [ ] 현재 환경의 Gemini를 우선 검증할 수 있고 OpenAI는 해당 키가 있을 때 선택적으로 실행한다. 키 없는 공급자는 skipped/not-run으로 기록한다.
- [ ] 정상 후보·정상 no-decision 합성 대화를 실제 AiAdapter·분석 API·임시 DB까지 연결한다. 운영 DB와 실제 Discord 대화는 사용하지 않는다.
- [ ] 모델 접근 불가·인증·호출 제한·deadline을 실제 오류로 보고하고 provider/model, 응답시간, 호출 수와 가능한 usage를 기록한다. 알 수 없는 비용은 0으로 표기하지 않는다.
- [ ] 이 티켓의 도구 구현과 실제 유료 실행을 구분한다. 실제 실행은 별도로 승인된 공급자·모델·호출/비용 범위에서만 수행한다.
- [ ] 호출 실패·중단 시 임시 서버·DB 정리가 끝나며 FE 변경은 없다.
