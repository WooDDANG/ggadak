# 07: 실제 대화 유형별 Decision 추출 품질 평가

**What to build:** 연결이 확인된 실제 모델을 정답이 있는 대화 사례로 평가해 잘못 잡은 결정·놓친 결정·허위 Rationale 인용을 수치와 실패 사례로 확인한다.

**Blocked by:** 05: Rationale 원문 인용의 진위 검증; 06: 실제 AI 연결을 별도 실행으로 확인하기.

**Status:** needs-triage

- [ ] 한국어·영어의 명시적 합의, 수렴, 합의 없는 제안, 부정·철회, 보류, 잡담·단순 일정, 다중 결정 및 근거 없는 사례에 독립적인 정답을 작성한다.
- [ ] 정답은 현재 mock 추출기의 결과에서 만들지 않는다. Decision 존재 여부, 핵심 내용, 확인 가능한 Rationale과 허용 인용을 구분한다.
- [ ] 각 실행에서 provider/model, prompt와 데이터셋 버전, 샘플 수, 반복 조건을 기록한다. 실제 공급자 응답을 분석·저장 경로까지 평가한다.
- [ ] Decision 탐지 precision/recall, 누락·오탐, 허위 인용 및 정상 구조화 응답 비율과 latency·usage를 보고한다. 작은 표본의 결과를 실대화 전체의 정확도로 단정하지 않는다.
- [ ] 기본 기대 기준은 제외 대화의 후보 0개, 허위 원문 인용 0개, 합의·다중 결정 정답의 누락 없는 처리로 두고 실제 평가 실패를 숨기지 않는다.
- [ ] 평가가 실패한 대화는 비용 없이 반복할 수 있는 공급자 응답 fixture와 오류 사례로 남긴다. prompt 변경은 기준 실행과 비교한다.
- [ ] 실제 실행의 호출/비용 상한과 임시 DB 사용은 연결 검증과 같은 경계를 따른다. FE 변경은 없다.
