# 03: 건너뛴 세션의 자동·수동 복구

**What to build:** 건너뛴 세션은 동기화와 독립적으로 최초 입력을 재분석하고, 성공하면 사람의 검수 결과를 보존하며 복구한다.

**Blocked by:** 02: 실패 세션 기록과 동기화 진행, ai-call-reliability/02: AI 실패 분류를 오류 코드로 확정

**Status:** ready-for-agent

- [ ] 최초 실패 후 1분, 첫 재시도 실패 후 5분에 최대 두 번 자동 재시도하고 소진 후 수동 재분석을 제공한다.
- [ ] 자동 재시도마다 seed를 시도 번호로 바꾼다(예: 42 + 시도 번호). 같은 시도 번호는 같은 seed로 재현한다.
- [ ] `output-truncated`(출력 상한에서 잘림)는 자동 재시도하지 않고 사유를 남긴 채 수동 재분석만 허용한다. 소유권 상실은 재시도 횟수에 넣지 않는다.
- [ ] 429는 Retry-After와 키별 제한을 따르고 가능한 다른 키를 사용한다. 설정 변경이 필요한 인증 실패는 자동 재시도하지 않는다.
- [ ] 자동·수동 재시도에 동일 세션 동시 실행 방지와 재시작 후 복구를 보장한다.
- [ ] 최초 입력과 실패한 세션을 재사용하고 성공한 형제 세션을 다시 분석하지 않는다.
- [ ] 성공 시 기존 중복 판별을 적용해 후보를 발행하고 실패 상태를 복구됨으로 바꾸며 사람이 수정·확정한 결과를 덮어쓰지 않는다.
- [ ] 손상 문제가 해결되면 현재 경고를 해제하고 손상 이력을 남긴다. 성공·중복·동시 요청·재시도 소진을 테스트한다.
