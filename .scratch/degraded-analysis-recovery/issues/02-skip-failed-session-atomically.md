# 02: 실패 세션 기록과 동기화 진행

**What to build:** 세션에 국한된 분석 실패가 후속 동기화를 막지 않도록 실패 기록과 Scan Range 진행을 원자적으로 확정한다.

**Blocked by:** 01: 손상된 분석 세션의 검증과 후보 발행, ai-call-reliability/02: AI 실패 분류를 오류 코드로 확정

**Status:** ready-for-agent

- [ ] 실패 세션은 정상적인 결정 없음과 구분해 원래 Scan Range, 세션 메시지 ID, 실패 종류·사유와 입력 참조를 영속적으로 남긴다.
- [ ] 실패 기록 없이 checkpoint가 전진하지 않으며 재시작·중복 전달 시 손실이나 중복 없이 복구한다.
- [ ] 한 세션 실패는 성공한 형제 세션과 후속 범위 진행을 막지 않는다. 실패 세션은 후보를 발행하지 않는다.
- [ ] 인증·DB 장애처럼 전체 분석에 영향을 주는 장애는 일시 중단하고 원인을 표시한다.
- [ ] 출력 형식 실패(빈 응답, 해석 불가, 잘림, Verify 형식 위반)와 AI 호출 타임아웃도 422 터미널이 아니라 세션 건너뜀으로 기록한다. 타임아웃 한 건으로 큐 전체를 백오프하지 않으며, 큐 전체 일시 중단은 provider 5xx, 모든 키의 인증·권한 실패, DB 장애에만 둔다(ADR-0028).
- [ ] 소유권 상실(lease-lost)로 중단된 호출은 건너뜀으로 기록하지 않는다.
- [ ] 부분 성공, 실패 직전·직후 재시작, 동기·비동기 경로와 checkpoint 경계를 통합 테스트한다.
