# 봇이 설치된 가입 서버만 선택 목록에 표시

**Status:** ready-for-agent

## Problem Statement

현재 FE는 로그인한 Discord 계정이 가입한 모든 서버를 선택 목록에 표시한다. 봇이 설치되지 않은 서버를 선택하면 카드·검수·설정 화면이 비어 보이거나 봇 관련 기능이 실패해, 사용자가 서비스에 연결된 프로젝트를 찾기 어렵다.

사용자는 가입 서버 전체가 아니라 **자신이 가입한 서버 중 GGADDAK 봇 설치가 확인된 서버만** FE에서 보고 선택하기를 원한다.

## Solution

선택 가능한 서버를 사용자 가입 정보와 GGADDAK 봇 설치 정보의 교집합으로 제공한다. FE의 로그인 직후, 재접속, 서버 전환, 설정 화면에서 같은 목록을 사용한다.

사용자 가입 여부는 사용자 OAuth 정보로, 봇 설치 여부는 해당 GGADDAK 봇의 신뢰할 수 있는 서버 관측으로 판단한다. FE가 받은 목록만 시각적으로 숨기는 데 그치지 않고, BE가 사용자에게 반환하는 서버 목록부터 필터링한다.

설치가 확인되지 않은 상태는 설치된 서버로 표시하지 않는다. 조회 장애는 정상적인 빈 목록과 구분하고, 유효한 로그인 세션을 유지한 채 재확인할 수 있게 한다. 설치 상태는 봇 프로세스의 온라인 상태나 개별 채널 읽기 권한과 구분한다.

## User Stories

1. As a 로그인 사용자, I want 내가 가입했고 GGADDAK 봇이 설치된 서버만 보고 싶다, so that 실제 연동된 프로젝트를 바로 선택할 수 있다.
2. As a 여러 서버 가입 사용자, I want 봇이 없는 개인·커뮤니티 서버가 목록에 나오지 않기를 원한다, so that 비어 있는 프로젝트를 잘못 선택하지 않는다.
3. As a 로그인 사용자, I want 봇이 있어도 내가 가입하지 않은 서버는 보이지 않기를 원한다, so that 다른 팀의 정보가 노출되지 않는다.
4. As a 신규 로그인 사용자, I want 첫 로그인 응답부터 필터링된 서버 목록을 받기를 원한다, so that 초기 화면에 전체 가입 서버가 잠깐 나타나지 않는다.
5. As a 재방문 사용자, I want 세션 복원 후에도 같은 서버 선택 정책이 적용되기를 원한다, so that 새로고침에 따라 목록이 달라지지 않는다.
6. As a 서버 목록을 새로고침하는 사용자, I want 명시적인 목록 조회도 같은 교집합을 반환하기를 원한다, so that 설정 화면과 메인 화면이 일치한다.
7. As a 여러 프로젝트 사용자, I want 조건을 충족하는 모든 서버를 선택할 수 있기를 원한다, so that 하나의 설치 서버만 임의로 선택되지 않는다.
8. As a 일반 멤버, I want 가입한 설치 서버를 관리자와 동일하게 목록에서 볼 수 있기를 원한다, so that 관리 권한 없이도 허용된 결정 기록을 조회한다.
9. As a 서버 관리자, I want 채널 설정 등의 관리 작업에는 기존 추가 권한 검사가 유지되기를 원한다, so that 목록 표시만으로 관리 권한이 부여되지 않는다.
10. As a 현재 서버 사용자, I want 선택한 서버가 여전히 조건을 충족하면 선택이 유지되기를 원한다, so that 재조회마다 프로젝트가 바뀌지 않는다.
11. As a 권한을 잃은 사용자, I want 탈퇴한 서버가 목록과 선택 상태에서 제거되기를 원한다, so that 이전 서버 캐시를 계속 보지 않는다.
12. As a 봇이 제거된 서버 사용자, I want 해당 서버가 선택 목록에서 빠지기를 원한다, so that 현재 연결된 프로젝트로 오인하지 않는다.
13. As a 선택 서버가 제거된 사용자, I want 남은 설치 서버로 이동하거나 안내 화면을 보기를 원한다, so that 오래된 서버 ID로 요청이 반복되지 않는다.
14. As a 설치 서버가 없는 사용자, I want 봇이 설치된 가입 서버가 없다는 안내를 보기를 원한다, so that 카드 데이터가 사라졌다고 오해하지 않는다.
15. As a 서버 관리자, I want 설치 후 재확인으로 새 서버가 목록에 나타나기를 원한다, so that 가입 서버 전체를 계속 노출하지 않아도 연결을 완료할 수 있다.
16. As a 설치 상태 조회 장애를 겪는 사용자, I want 정상 빈 목록과 장애 안내가 구분되기를 원한다, so that 불필요하게 봇을 재설치하지 않는다.
17. As a 일시 장애를 겪는 사용자, I want 다시 확인할 때 기존 로그인이 유지되기를 원한다, so that Discord 인증을 처음부터 반복하지 않는다.
18. As a 봇이 일시 오프라인인 서버 사용자, I want 설치 여부와 온라인 여부가 구분되기를 원한다, so that 프로세스 중단만으로 미설치 판정을 받지 않는다.
19. As a 서버를 빠르게 전환하는 사용자, I want 이전 서버의 늦은 응답이 새 화면을 덮어쓰지 않기를 원한다, so that 다른 프로젝트의 카드를 보지 않는다.
20. As a 계정을 전환하는 사용자, I want 이전 계정의 서버 목록·선택·캐시가 제거되기를 원한다, so that 계정 간 정보가 섞이지 않는다.
21. As a FE 개발자, I want 서버 선택에 쓰는 모든 BE 응답에 같은 정책이 적용되기를 원한다, so that FE가 서로 다른 목록을 직접 조합하지 않는다.
22. As a 운영자, I want 이벤트와 필요한 재검증으로 설치 목록을 갱신하기를 원한다, so that 고정 주기의 전체 Discord 재조회가 다시 도입되지 않는다.

## Implementation Decisions

- 목록 조건은 사용자 가입 확인 AND GGADDAK 봇 설치 확인이다. 서버 관리자 여부, 모니터링 채널 유무, 저장된 카드 수는 목록 포함 조건이 아니다.
- BE의 로그인·브라우저 세션 복원·사용자 서버 목록 조회 등 서버 목록을 반환하는 모든 사용자 경로에 동일한 필터를 적용한다. 로그인 응답에 포함된 최신 목록도 예외가 아니다.
- 필터링 결과의 서버 ID·이름·아이콘·owner·permissions는 기존 계약을 유지한다. 사용자에게 가입 서버 전체를 반환하고 FE에서만 숨기는 방식은 사용하지 않는다.
- Bot Installation Status의 installed만 목록 포함에 사용한다. 다른 봇 설치, 봇 온라인, 채널 접근 권한은 이를 대체하지 않는다.
- 설치 판정은 기존 Bot 관측·설치 확인 경계를 재사용한다. 최신의 완전한 설치 서버 관측이 있으면 이를 사용자 가입 정보와 교차 확인한다. 관측이 없거나 연결 연속성이 불명확하면 필요한 시점에 권한 있는 Discord 확인으로 보완한다.
- 서버 목록 조회마다 모든 가입 서버에 대해 여러 설치 확인 요청을 무조건 발생시키지 않는다. 설치 서버 인벤토리와 기존 캐시를 재사용하고 동시 재확인을 공유한다. 목록이 페이지로 나뉘는 외부 조회는 전체 페이지의 누락·실패를 고려한다.
- Bot의 실제 서버 제거는 설치 정보와 목록을 무효화한다. 사용자 탈퇴는 가입 정보와 목록을 무효화한다. 신뢰할 수 있는 새 확인을 거쳐야 목록에 복귀한다.
- Bot 프로세스 오프라인이나 Discord unavailable만으로 not_installed를 확정하지 않는다. 설치 여부를 확인할 수 없으면 확인 불가로 처리한다.
- unknown이나 조회 장애의 서버를 정상 installed 항목으로 반환하지 않는다. 확인 불가를 정상적인 서버 없음과 구분할 수 있도록 응답 상태와 FE 안내를 제공한다. 일시 오류만으로 사용자 인증 세션을 삭제하지 않는다.
- 필터링된 목록에 현재 선택 서버가 남아 있으면 유지한다. 없으면 이전 서버 요청을 취소하고 캐시를 정리한 뒤 남은 적격 서버를 선택한다. 없으면 서버 없음 또는 확인 불가 화면으로 전환한다.
- 서버가 0개일 때 미설치 서버를 임의로 선택해 데이터 요청하지 않는다. 기존 설치 안내 수단을 제공할 수 있지만, 이번 범위에서 일반 서버 선택 목록을 전체 가입 서버로 되돌리지 않는다.
- 봇 설치 후 포커스 복귀·수동 재확인·재접속 시 목록을 다시 확인할 수 있게 한다. 주기적인 전체 권한/설치 조회 타이머는 추가하지 않는다.
- 사용자 소속 확인과 서버별 기존 데이터 접근 검사는 계속 수행한다. 이번 요청의 직접 대상은 서버 선택 목록이며, 봇 제거 후 기존 Decision Record를 삭제하거나 기존 데이터 API의 접근 정책을 일괄 변경하는 작업은 포함하지 않는다.
- 기존의 미설치 서버 선택 후 설치 안내 동작은 이 목록 정책으로 변경된다. 관련 인증·설치 안내 계약과 예제를 구현과 함께 갱신한다.
- FE는 독립 저장소의 작업 브랜치와 PR로만 수정한다. 부모 저장소의 submodule 포인터는 검증한 FE 커밋을 명시적으로 기록한다.

## Testing Decisions

- 주 검증 경계는 기존 FE→실제 BE HTTP 연동이다. 외부 Discord 가입·설치 관측만 제어하고, 내부 함수 호출 횟수나 구현 형태 대신 사용자에게 보이는 목록·선택·응답을 검증한다.
- 선행 사례는 기존 실제 HTTP 인증·서버 격리 테스트와 Bot 설치 상태 테스트, 브라우저의 서버 선택·계정 전환 검증이다. 이 경계를 우선 확장한다.
- 가입 O/설치 O, 가입 O/설치 X, 가입 X/설치 O, 가입 X/설치 X 조합에서 첫 번째 서버만 표시되는지 확인한다.
- 로그인, 세션 복원, 명시적 서버 목록 조회가 동일한 결과를 반환하는지 확인한다.
- 봇이 설치돼 있지만 카드가 없거나 모니터링 채널이 없는 서버도 목록에 표시되는지 확인한다.
- 서버 소유자가 아닌 일반 멤버도 목록에는 포함되고 관리 작업은 기존 권한에 따라 거절되는지 확인한다.
- 사용자 탈퇴·봇 제거·재설치·기억한 서버 소멸·계정 전환 후 목록과 선택·데이터 캐시가 갱신되는지 확인한다.
- 봇 오프라인, unavailable, 관측 누락, 외부 API 오류와 정상적인 설치 서버 0개를 구분한다. 오류 응답으로 세션을 폐기하거나 미설치를 확정하지 않는지 확인한다.
- 이벤트와 목록 재조회가 경합하거나 이전 요청 응답이 늦게 도착해도 제거된 서버가 다시 표시되지 않는지 확인한다.
- 외부 목록의 다중 페이지와 동시 요청을 포함해 일부 결과를 전체 목록으로 확정하지 않는지 확인한다.
- idle 상태의 시간 경과만으로 Discord 전체 목록 조회가 발생하지 않으며, 필요한 설치 후 재확인과 장애 복구는 동작하는지 확인한다.
- 사용자에게 이 FE→BE 검증 범위를 제시했다. 추가 요구가 오면 같은 외부 동작 경계에서 반영한다.

## Out of Scope

- 서버별 결정 기록의 이동·삭제·승인·상태 변경 및 카드 재생성.
- 모든 가입 서버에 봇을 일괄 설치하거나 자동 초대하기.
- 개별 채널 읽기 권한이나 봇 온라인 상태를 설치 여부로 통합하기.
- 서버별 웹 External Feedback 신규 기능과 별도의 웹 실시간 푸시.
- 봇 미설치 서버의 기존 기록 접근을 전면 금지하는 별도의 인가 정책 변경.
- 운영 DB migration, Discord Portal 설정 또는 FE PR의 자동 merge.

## Further Notes

- 사용자가 직접 요청한 제품 정책 변경이다. 이전의 전체 가입 서버 선택·미설치 서버별 설치 안내와 충돌하는 부분은 새 명세를 우선한다.
- 현재 데이터가 있는 가입 서버는 우땅의 마크이며 다른 가입 서버는 비어 있었다. 이는 문제를 발견한 배경이며, 특정 서버명·카드 수를 목록 필터 조건으로 하드코딩하지 않는다.
- 로그인 보완 작업은 진행 중인 FE PR과 별도 변경으로 추적할 수 있다. 현재 submodule 연결과 전용 서비스 pane은 유지한다.
- 본 산출물은 구현 명세다. 서버 목록 필터 구현과 배포가 이미 끝났다는 의미는 아니다.
