# 04: 실패한 분석의 명시적 재분석 지원

**What to build:** 사용자가 실패한 분석을 선택해 보관된 입력으로 새 분석을 시작하고 진행·완료·실패 상태를 확인할 수 있게 한다. 성공한 새 분석은 Review Queue로 연결된다.

**Blocked by:** 01: 분석 실패 원인과 진행 상태 표시.

**Status:** ready-for-agent

- [ ] 실패 분석의 복구 동작이 기존 terminal 요청의 단순 재조회에 그치지 않고 새로운 분석 식별자를 생성한다.
- [ ] 기존 실패 기록과 새 분석의 관계를 보존하고 새 분석에 적용할 Provider·모델·프롬프트 설정을 명확히 한다.
- [ ] 동일 동작의 중복 클릭이나 네트워크 재전송이 중복 분석을 만들지 않도록 멱등성을 보장한다.
- [ ] 서버 접근 권한을 검증하며 다른 서버의 보관 입력으로 재분석할 수 없다.
- [ ] 보관 입력이 없거나 만료된 경우 복구 불가 이유와 새 스캔 필요 여부를 안내한다.
- [ ] 재분석 성공 시 후보를 Review Queue에 게시하고 기존 Evidence Hash 및 검수 결과를 존중한다. 기존 승인·거절·수정 결과를 덮어쓰지 않는다.
- [ ] 실제 저장·재시작·명시적 재분석·결과 조회 경로와 중복 요청을 검증한다. 요청 내 세션의 원자적 게시 정책은 유지한다.
