# 03: 보고된 오류를 해결하는 수정 단계 개선

**What to build:** 분석 중 발견한 오류를 위치·위반 규칙·관련 요소와 함께 수정 단계에 전달하여, 정상 요소를 보존하면서 실제 오류를 해결한다. 의미 검증의 수정 요구는 명시적인 분석 규칙과 대화 근거에 기반한다.

**Blocked by:** 02: 그래프 생성 계약과 검증 규칙 일치.

**Status:** ready-for-agent

- [ ] 구조 및 의미 검증 오류가 관련 노드·연결·필드와 위반 규칙을 식별할 수 있는 피드백으로 수정 요청에 전달된다.
- [ ] 기존 요소 ID와 오류와 무관한 정상 정보를 보존하도록 수정 요청을 구성하고, 수정 결과에 전체 구조·의미 검증을 적용한다.
- [ ] 실제 위반과 단순한 표현 선호 또는 비차단 제안을 구분하는 판단 기준을 명시한다. 근거 없는 합의·대안 기각·담당자 추론을 허용하지 않는다.
- [ ] 실제 관측된 잘못된 연결, 잘못된 상태값, 명시되지 않은 대안 기각 및 근거 상태 오류를 평가 사례에 포함한다.
- [ ] 기존 한 번의 수정 제한, 호출 예산, 취소와 시간 제한을 유지하며 숨은 재시도를 추가하지 않는다.
- [ ] 수정 후 새 오류가 생기거나 오류가 남으면 실패하고 저장하지 않는 동작을 검증한다. 구조 검증을 통과해도 의미 검증에서 실패하는 사례를 포함한다.
