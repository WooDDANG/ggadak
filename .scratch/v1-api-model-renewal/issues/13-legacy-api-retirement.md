# 13: 기존 API·클라이언트 전환 완료 및 제거

**What to build:** 모든 화면과 봇이 지원되는 계약을 사용하며 이전 검수 경로와 중복 API를 제거한 상태로 전체 흐름이 동작한다.

**Blocked by:** 08: 결정 카드 편집, 10: 대시보드 요약, 11: Why 자연어 검색, 12: Decision Timeline

**Status:** ready-for-agent

- [ ] 프론트·봇·테스트의 실제 호출자를 조사해 기존 API 호출을 전환하고 등록된 Discord 충돌 버튼 검수 경로를 웹 중심 검수 흐름으로 정리한다.
- [ ] 기존 conflict·결정 webhook 등 제거 대상은 동등한 지원 경로와 호출자 전환을 검증한 뒤 제거한다. 분석·정책·체크포인트·후보 이력 등 필요한 내부 API는 유지하고 인증 경계를 검증한다.
- [ ] 기존 컬럼·domainJson·상태 별칭 등 임시 호환 구조는 이전 데이터와 모든 호출자의 전환이 확인된 항목만 제거한다.
- [ ] 최종 ERD·Prisma 모델·OpenAPI·생성 클라이언트를 일치시키고 로그인부터 설정·동기화·검수·편집·검색·타임라인까지 회귀 검증한다.
- [ ] 운영 DB 변경은 검증된 마이그레이션과 백업·복구 절차를 준비하고 별도 승인 범위에 따라 수행한다.
