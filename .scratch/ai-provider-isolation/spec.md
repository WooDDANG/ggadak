# AI 분석 알고리즘과 Provider 경계 명세

Status: ready-for-agent

## Problem Statement

유지보수자는 AGY와 NVIDIA를 이용해 Decision 분석 알고리즘을 실행할 때 알고리즘과 각 AI 실행 방식이 명확히 격리되어 있는지 이해하고 변경하기 어렵다. 현재 분석 흐름은 단계별 작업을 실행 인터페이스에 위임하지만, 어댑터가 Provider 생성, 프롬프트 구성, 설정 검증과 계측을 함께 담당한다. 저장된 분석 설정의 Provider 이름과 어댑터 생성 시 선택된 실제 Provider가 달라질 가능성도 검토해야 한다.

## Solution

Decision 분석의 단계와 정책은 공통 실행 계약을 통해 동작하고, AGY CLI와 NVIDIA HTTP의 구체적인 호출 방식은 각 Provider 경계에 둔다. 분석 재개 시 저장된 설정과 실제 실행 대상이 일치하도록 보장하며, 지원할 수 없는 설정은 명시적으로 실패한다. 각 경계를 기존 주입 지점에서 독립적으로 검증한다.

## User Stories

1. 유지보수자로서, 분석 알고리즘이 Provider의 구체적인 호출 방식을 몰라도 되기를 원한다. 그래야 알고리즘을 독립적으로 변경할 수 있다.
2. 유지보수자로서, AGY CLI 세부 구현을 다른 분석 단계에 전파하지 않기를 원한다. 그래야 CLI 변경의 영향을 제한할 수 있다.
3. 유지보수자로서, NVIDIA HTTP와 SDK의 세부 구현을 다른 분석 단계에 전파하지 않기를 원한다. 그래야 API 연동 변경의 영향을 제한할 수 있다.
4. 운영자로서, 설정한 Provider가 실제로 호출되기를 원한다. 그래야 실행 대상이 예측 가능하다.
5. 운영자로서, 저장된 분석을 재개할 때 그 분석의 Provider 설정이 존중되기를 원한다. 그래야 재시작이 실행 의미를 바꾸지 않는다.
6. 운영자로서, 저장된 Provider를 사용할 수 없으면 명확하게 실패하기를 원한다. 그래야 다른 Provider로 실행된 결과를 오인하지 않는다.
7. 운영자로서, Provider 장애 시 자동으로 다른 Provider로 전환되지 않기를 원한다. 그래야 기존 운영 정책이 유지된다.
8. 운영자로서, 실제 호출 대상과 기록된 Provider 및 모델이 일치하기를 원한다. 그래야 시도 기록과 메트릭을 신뢰할 수 있다.
9. 유지보수자로서, 추출·검증·수정 단계의 프롬프트와 스키마 선택이 공통 정책에 따르기를 원한다. 그래야 Provider 교체가 분석 의도를 바꾸지 않는다.
10. 유지보수자로서, 각 단계에 지정된 모델이 실제 요청에 전달되기를 원한다. 그래야 단계별 모델 설정이 유지된다.
11. 운영자로서, 입력 및 출력 제한과 Provider별 지원 차이가 명확하기를 원한다. 그래야 지원되지 않는 제한이 적용된 것처럼 보이지 않는다.
12. 운영자로서, 호출 취소와 시간 초과가 실행 중인 Provider에 전달되기를 원한다. 그래야 사용 중인 리소스를 회수할 수 있다.
13. 운영자로서, Provider 오류가 기존 분석 실패 및 재시도 정책에 반영되기를 원한다. 그래야 큐와 체크포인트의 동작을 예측할 수 있다.
14. 유지보수자로서, 분석 알고리즘을 실제 AI 자격증명 없이 검증하기를 원한다. 그래야 빠르고 재현 가능한 검사를 수행할 수 있다.
15. 유지보수자로서, 두 Provider가 각각 공통 요청과 결과 계약을 지키는지 검증하기를 원한다. 그래야 통합 시 차이를 일찍 발견할 수 있다.
16. 사용자로서, 기존 Decision Candidate 분석과 Review Queue 흐름이 유지되기를 원한다. 그래야 내부 경계 개선으로 기존 사용 방식이 바뀌지 않는다.

## Implementation Decisions

- 범위는 BE Decision 분석의 코드 의존성과 실행 계약 격리다. 실제 프로세스·자격증명·인프라 격리 확대는 합의되지 않았으며 별도 결정이 필요하다.
- 분석 워크플로는 추출, 구조 검사, 의미 검증, 제한된 수정 및 재검증, 체크포인트와 호출 예산을 소유한다. Provider는 공통 요청을 자신의 실행 방식으로 변환하고 결과와 오류를 반환한다.
- Provider 선택과 생성은 알고리즘 및 단계별 프롬프트 정책과 구분된 조립 책임으로 둔다. 기존 주입 지점을 우선 활용하고 불필요한 추상화는 추가하지 않는다.
- 저장된 설정의 Provider와 실제 선택이 일치해야 한다. 지원되지 않거나 사용할 수 없는 설정은 호출 전에 명확히 실패하거나 해당 Provider의 오류를 반환한다. 다른 Provider로 묵시적으로 전환하지 않는다.
- 모델 선택, 프롬프트 버전, 출력 스키마, 사용량, 취소, 시간 초과와 메트릭의 기존 의미를 보존한다. 실제 실행 대상과 시도 기록 및 메트릭이 일치하도록 한다.
- AGY와 NVIDIA의 토큰 제한 및 구조화 응답 능력 차이를 숨기지 않는다. AGY의 정확한 입력 토큰 사전 검사 불가 및 출력 사용량 사후 검사, NVIDIA의 기존 출력 제한 동작을 유지한다.
- 기존 AGY 임시 작업공간과 자식 환경 제한 및 정리 동작을 보존한다. NVIDIA thinking 및 로깅 정책은 기존 ADR을 따른다.
- 분석 데이터와 외부 API 계약, 영속화된 체크포인트의 호환성을 유지한다. 변경이 불가피하다면 별도 호환 및 마이그레이션 결정을 먼저 마련한다.
- NVIDIA 기본값, AGY 병행 지원, 자동 전환 금지는 승인된 NVIDIA Provider ADR을 따른다. OpenAI 임베딩은 별도 기능이다.

## Testing Decisions

- 좋은 테스트는 내부 메서드 호출 순서나 파일 배치보다 관찰 가능한 결과, 실제 요청 대상, 오류, 취소, 기록과 재개 동작을 검증한다.
- 가능한 가장 높은 기존 경계인 분석 실행 인터페이스에 테스트 구현을 주입하여 추출·검증·수정, 예산, 취소 및 체크포인트 재개를 검증한다. 기존 분석 API 및 서비스 픽스처 테스트를 선례로 삼는다.
- 기존 Provider 인터페이스와 주입 가능한 CLI 전송 및 NVIDIA 클라이언트 경계에서 각 Provider의 요청·응답·오류·취소 및 지원 제한을 검증한다. 기존 Provider 테스트를 확장한다.
- 저장된 Provider와 현재 조립 설정이 다른 재개 시나리오에서 실제 대상과 시도 기록이 일치하거나 안전하게 실패함을 검증한다. 숨은 전환이 발생하지 않아야 한다.
- 단계별 모델 및 스키마, 사용량과 메트릭의 성공·실패 동작은 기존 어댑터 테스트를 선례로 검증한다. 실 Provider 호출은 자동 테스트의 필수 조건이 아니다.
- 테스트 경계는 사용자 확인을 요청한 제안이며, 답변에 따라 조정한다.

## Out of Scope

- 새로운 AI Provider 추가, 자동 장애 전환 또는 모델 품질 개선.
- 프롬프트 및 Decision 분석 정책의 기능 변경.
- 기존 격리를 넘어서는 컨테이너화, OS 보안 경계, 자격증명 구조 변경.
- OpenAI 임베딩, 프론트엔드 및 공개 API의 기능 변경.

## Further Notes

사용자는 격리를 더 정확하게 만들고 싶다고 요청했지만 격리의 구체적 범위는 아직 확인되지 않았다. 이 명세는 코드 및 계약 격리를 작업 가정으로 삼는다. 제안한 티켓 분할은 아직 승인되지 않았으며, 이 명세의 발행이 티켓 분할에 대한 승인을 의미하지 않는다.
