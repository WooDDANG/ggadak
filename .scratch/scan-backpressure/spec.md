# 전수검사 부하 제어 구현안

Status: ready-for-agent

사용자와 합의한 운영 정책은 [인터뷰 기록](./map.md)을 따른다. 사용자 확인을 반영해 10개의 [로컬 이슈](./issues/)로 발행했다. 문서화·티켓 발행을 완료했으며 코드 구현은 아직 수행하지 않았다.

## 두 큐의 책임과 병행

- Bot 전달 큐는 아직 BE 영속 수신 확인을 받지 못한 데이터만 전달 책임을 가진다. BE는 수신 입력과 후속 처리 의도를 영속 보존한 뒤 즉시 수신을 확인한다. Bot은 이 확인 이후 AI 결과를 기다리지 않고 해당 전달을 완료한다. 응답 유실은 같은 식별자로 재전송해 멱등 확인한다.
- BE 분석 큐는 수신 이후의 대기·AI 실행·재시도·완료·보관 실패를 책임진다. HTTP 연결·Bot 연결 수명과 독립적으로 동작하고 재시작 후 복구한다. 수신 확인 전에 입력만 저장되고 처리 의도가 유실되는 간극을 허용하지 않는다.
- Bot의 수집·전달과 분석 결과 반영은 별도 비동기 흐름이다. BE는 결과를 영속 보관하고 Bot은 중복 없이 반영하며 단절 이후 재조회한다. 결과 전달 채널로 SSE나 WebSocket을 도입할지는 확정하지 않는다. HTTP 자체가 병목이라는 측정 근거는 없다.
- 초기 구현은 기존 Prisma/SQLite와 기존 영속 journal을 재사용하며 새 메시지 브로커를 요구하지 않는다. 대기 작업 수와 입력 바이트·디스크 한도를 설정하고 BE가 허용한 용량 안에서만 Bot이 다음 전송을 진행한다.
- 수신 요청·구간·미완료 저장량의 유한한 기본 제한은 첫 수신 기능부터, 분석 동시 실행 기본값 1은 첫 worker부터 적용한다. 후속 우선순위 기능이 완성될 때까지 무제한으로 실행하지 않는다.

## 채널 처리 소유권

- BE가 현재 채널과 다음 행동을 소유한다. Bot은 지정된 한 채널의 데이터만 구간별 순차 전송하며 BE 확인·다음 지시 없이 다음 채널로 진행하지 않는다. 기존 Sync Job 잠금·lease·owner 검증을 재사용한다.
- 수집 시작 시 검사 상한을 고정하고 구간 식별자·경계·내용 검증값으로 중복 전송과 누락을 식별한다. BE는 영속 저장 후 수신을 확인한다. 빈 채널을 포함해 명시적인 수집 완료 선언과 예상 구간 정보로 전체 수신을 검증한다.
- 한 채널 전체 수신·검증 후 BE가 보관 입력을 사용해 구간별로 분석한다. 전체 채널을 하나의 AI 입력이나 메모리 배열로 합치지 않는다. 수신 완료는 분석 완료나 Channel Checkpoint 전진을 뜻하지 않는다.
- 누락·전송 손상 구간은 Bot에 선택 재전송을 지시한다. AI 실패는 BE 보관 입력과 workflow를 사용해 재시도한다. 재시도와 명시적 재분석의 요청 식별자 규칙을 구분한다.
- 채널 전송 순서는 유지하지만 A의 분석 완료가 B 수집의 필수 조건은 아니다. A 전체의 영속 수신·검증을 마치고 BE에 수신 여유가 있으면 A 분석 중에도 BE가 B를 지시한다. 이전의 'A 분석 종료 후 B 전송' 정책은 수집·전달과 분석 병행 합의로 대체한다.
- 수집·전달의 재시도 소진은 해당 채널을 실패로 보존하고 다음 채널을 진행한다. 분석 재시도 소진은 BE에서 별도로 보존하며 이미 전달 중인 채널을 취소하지 않는다. 실패 구간은 웹에서 재시도할 수 있고 완료나 성공으로 표시하지 않는다. 전체 검사는 수신 완료와 분석 최종 상태를 함께 판단한다.
- 전체 채널의 수신 완료 전에 저장 한도를 넘으면 수신·분석의 상호 대기를 만들지 않는다. 용량 초과를 명시하고 확인된 자료·범위를 보존해 한도 조정 후 같은 검사에서 이어받는다. 채널별 용량 초과는 실패로 보존해 다른 채널에 진행 기회를 주되, 디스크 전체 부족은 전체 수신 불가 상태로 표시한다. 조치 없이 같은 입력을 자동 반복 전송하지 않는다.

## 완료 자료와 운영 관측

- 완료 자료 정리는 별도 이슈로 구현한다. Bot 확인 원문·BE 완료 입력·결과 반영 확인·검사 범위·중복 방지 기록의 정리 조건을 분리한다. 미완료·실패·미확인 자료와 체크포인트 공백 복구 자료는 자동 삭제하지 않는다.
- 원문 정리 후에도 늦은 재전송이 새 분석을 만들지 않도록 최소 중복 방지 기록은 초기 정책에서 자동 만료하지 않는다. Decision Record와 근거·검토 이력은 분석 입력 정리와 구분한다. 조회·재분석 기능의 보존 계약 없이 필요한 입력을 삭제하지 않는다.
- 정리는 제한된 단위로 수행하고 사용량·회수량을 관측한다. SQLite 논리 삭제와 실제 물리 파일 여유를 구분하며, 공간 부족을 미확인 데이터 삭제로 숨기지 않는다.
- 요청 식별자로 전달 대기·BE 분석 대기·AI 실행·결과 반영 지연을 운영 중 구분한다. 시간 오차와 재시도를 구분하고 원문·자격증명을 지표에 남기지 않는다.
- 구 경로에서 이미 완료했으나 Bot이 응답을 잃은 작업과 아직 실행 중인 작업을 구분해 큐 전환 시 원래 식별자·입력·결과를 재사용한다. worker 이중 실행을 막고 전환 중 재시작을 검증한다.

## 처리와 수집

- BE가 모든 진입점의 분석 실행 한도를 소유한다. 초기값은 전체 1개이며 설정 가능하게 한다. 기존 채널별 직렬 실행도 유지한다. 대기·백오프 중인 작업은 실행 슬롯을 차지하지 않는다. Bot의 채널별 순차 전달과 BE의 채널별 분석 순서를 별도로 관리한다.
- 슬롯 선택 시 실시간·수동 요청을 전수검사보다 우선하되, 전수검사가 무기한 밀리지 않도록 연속 우선 처리 횟수를 제한한다. 초기 기준은 우선 작업 5개 처리 뒤 준비된 전수검사 1개에 기회를 주는 것으로 하며 측정 후 조정 가능하게 한다.
- 채널 전체 메시지를 메모리에 모으는 흐름을 페이지 단위 수집과 BE의 영속 수신 확인으로 바꾼다. 기존 Discussion Context 구성과 Scan Range 연속성은 보존한다. Bot은 BE가 허용한 전송 범위를 넘겨 데이터를 생산하지 않는다. 채널 전체의 수신 완료 후 분석하므로, 수신 중인 다음 구간의 허용 조건은 이전 구간의 분석 완료가 아니라 영속 수신 확인이다. 기존 보관 실패는 삭제하지 않는다.

## 부하와 실패

- BE·AI의 공통 요청 제한·일시 장애에는 새 전수검사 분석을 대기시키고 수신 용량에 맞춰 추가 수집·전송을 제한한다. Bot의 전달 재시도와 BE의 분석 재시도는 각각 영속 책임 경계에서 수행한다. 기존 유한 지수 백오프와 jitter를 재사용하고 제공된 Retry-After를 존중한다. 대기 종료 후 단일 요청으로 회복을 확인한다. 채널별 영구 권한 오류는 전체 장애로 확대하지 않는다.
- 동일 Analysis Request 식별자, 완료 결과 재사용, 실패 보관, 연속 완료 Scan Range에 따른 Channel Checkpoint 규칙은 ADR-0020을 유지한다.
- 중복 타이머·복구 실행은 합치고, 반응 정리 성공 여부를 기록해 같은 작업을 매초 다시 예약하지 않는다. 실패한 정리는 제한된 간격으로 재시도하고 재시작 후 필요한 미완료 정리는 복구한다.
- 체크포인트는 완료 범위 변경과 시작 시 복구를 중심으로 동기화한다. 처리 중 새 변경은 잃지 않으며 BE 장애 후 재시도한다. 변경이 없어도 모든 과거 채널을 매초 조회하지 않는다.
- 완료 이력 전체의 주기적 재전송·DB upsert를 변경분 전송으로 바꾼다. BE 확인 전에는 변경분을 제거하지 않는다. 초기/복구 동기화는 크기를 제한해 나누며, Bot 생존 확인은 별도로 유지해 기존 15초 신선도 판정과 호환한다.

## 표시

- 전수검사는 개별 Discord 메시지 반응을 만들지 않는다. 명령 실행자에게 시작·종료 또는 실패·대기 요약을 제공하고 웹에서 진행률과 보관 실패를 확인한다.
- 실시간·수동 분석 반응은 상태 변경 시 갱신하며 반복 복구가 Discord API 요청을 계속 발생시키지 않게 한다.

## 검증

- 여러 채널과 진입점에서 동시에 요청해도 전체·채널별 실행 한도를 넘지 않는다. 실시간 우선 처리와 전수검사 진행 기회를 모두 검증한다.
- 요청 제한·네트워크 장애·BE 재시작 후에도 요청 식별자와 완료 범위를 보존한다. 재시도 대기는 다른 작업의 실행 슬롯을 막지 않는다.
- 긴 분석 중 반복 복구 타이머를 호출해도 반응 정리와 복구 작업이 중복 대기열을 만들지 않는다.
- 변경 없는 상태에서 체크포인트 조회·완료 이력 갱신이 과거 기록 수에 비례해 매초 반복되지 않는다. 변경분 유실·중복 확인·시작 시 복구와 생존 판정을 검증한다.
- 대형 채널 수집의 메모리 사용을 전체 이력 크기로부터 분리하고, 구간 경계의 누락·중복 및 체크포인트 선행을 검증한다.
- 느린 AI 중에도 BE 저장 확인 후 Bot 전달이 진행되고, 입력 용량 포화 때 수집·전송이 대기하는지 검증한다. Bot 미확인 전달과 BE 대기 분석을 별도로 측정한다. 결과 반영·전달의 병행에서도 단절·재시작·응답 유실이 데이터·완료 결과를 잃지 않게 한다.
- 실제 Discord 전송이나 유료 AI 호출 없이 fake adapter·가상 시간·격리 DB로 우선 검증한다. 실제 부하 검증은 처리량·대기량·요청 수·오류율을 함께 측정해 완료 여부를 판단한다.
- 채널 크기가 한도보다 큰 경우의 교착 방지·한도 조정 후 재개, 데이터 정리 경합, 운영 병목 지표, 구 worker와 새 큐의 전환·응답 유실을 통합 검증한다.

새 메시지 브로커나 저장소 교체는 포함하지 않는다. 실제 서버 메시지 전송이나 실행 중인 검사의 임의 취소는 이 설계 확인에 포함하지 않는다.
