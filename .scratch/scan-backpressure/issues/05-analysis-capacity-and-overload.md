# 05: BE 분석 한도·우선순위와 전송량 제어

**What to build:** BE가 AI 실행과 대기 데이터의 양을 통제해 전수검사 중에도 실시간 분석·로그인·웹 조회 여유를 유지한다.

**Blocked by:** 04 — 채널 순차 전달과 분석의 병행

**Status:** ready-for-agent

- [ ] BE가 실시간·수동·전수검사·재시도에 공통 분석 실행 한도를 적용한다. 초기 전체 동시 실행은 1개이고 기존 채널별 직렬 실행도 유지한다.
- [ ] 실시간·수동 작업을 우선하되 준비된 전수검사에 진행 기회를 준다. 초기 우선 작업 5개 후 전수검사 1개 기준을 설정 가능하게 한다.
- [ ] BE의 수신 허용 여부와 대기 이유를 Bot에 전달한다. 큐가 가득 차면 미수신 데이터를 Bot에 보존하고 무제한 업로드를 막는다. 대기 건수뿐 아니라 바이트·큰 입력 처리와 보관 실패 용량도 고려한다.
- [ ] 수신 단계의 기본 제한과 worker의 기본 실행 한도를 확장해 우선순위·동적 대기를 적용한다. 한 채널의 크기가 허용량을 넘으면 큐가 비기를 영구 대기하지 않고 운영자가 용량 초과와 필요한 조치를 확인할 수 있게 한다. 부분 수신·보관 실패 데이터도 실제 저장 사용량에서 제외하지 않는다.
- [ ] 공통 과부하에서는 신규 전수검사 분석과 추가 데이터 유입을 제한한다. 채널별 영구 오류와 구분하며 실행 중 작업은 마무리하고 유효한 Retry-After·백오프 후 단일 요청으로 회복을 확인한다.
- [ ] 연결·수신 여유·AI 대기를 서로 구분해 표시한다. 대기한 작업이 실행 슬롯을 붙잡거나 새 재시도 폭주를 만들지 않는다.
- [ ] 가상 시간·느린 provider·큰 입력 fixture로 전체 한도·우선순위·공정성·용량 포화·재개·재시작·로그인과 조회를 검증한다.
