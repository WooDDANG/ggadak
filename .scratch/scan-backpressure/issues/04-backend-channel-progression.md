# 04: 채널 순차 전달과 분석의 병행

**What to build:** Bot은 채널 순서대로 데이터를 전달하면서 BE의 이전 채널 AI 분석과 다음 채널 수집을 겹쳐 진행한다.

**Blocked by:** 03 — 전달 재전송과 분석 재시도의 책임 분리

**Status:** ready-for-agent

- [ ] 기존 'A 분석 종료 후 B 전송' 조건을 대체한다. BE가 A 전체의 영속 수신·완전성을 확인하고 수신 여유가 있으면 A 분석 중에도 B를 지시한다. Bot은 한 번에 지정된 한 채널만 수집·전송한다.
- [ ] Bot→BE 전송은 구간별 수신 확인을 따르며 BE가 제한하는 대기 작업 수·보관 입력 바이트·미완료 수신 용량을 넘지 않는다. 수집 진행용 디스크 자료도 상한·복구 정책을 가진다.
- [ ] 다른 분석의 완료로 공간이 생길 수 있는 일시 포화와, 현재 미완료 채널 자체가 한도를 넘어 분석 시작도 못 하는 용량 초과를 구분한다. 후자는 보관 실패로 기록해 다음 채널 진행 기회를 주고, 한도 조정 후 동일 범위를 이어받는다. 보존 데이터가 전체 디스크를 채운 경우는 전체 수신 불가 상태를 명시한다.
- [ ] 서버별 채널 snapshot·검사 상한·lease·owner를 영속 관리하고 중복 claim·Bot 재시작·늦은 응답으로 채널 전송 순서가 깨지거나 두 producer가 동시에 실행되지 않게 한다.
- [ ] 수집·수신 실패가 한도를 소진한 채널은 실패로 보존하고 다음 채널로 진행한다. 분석 실패는 별도로 보존하며 이미 진행한 다른 채널의 수신을 취소하지 않는다.
- [ ] 웹에서 전달 진행과 분석 진행을 구분하고 수신 확인을 전체 검사 성공으로 표시하지 않는다. 채널별 최종 분석 결과가 결정된 뒤 전체 결과를 확정한다.
- [ ] 느린 AI에서도 다음 허용 채널 전송이 진행되고 수신 상한에 도달하면 멈추며 용량이 생기면 재개하는 동작을 검증한다. 기존 진행 중 검사도 데이터 유실·이중 실행 없이 전환한다.
- [ ] 기존 동기 분석의 미응답 요청을 새 큐로 인계할 때 BE에서 이미 완료된 요청, 아직 실행 중인 요청, Bot이 응답을 잃은 요청을 구분해 원래 식별자·입력·결과를 재사용한다. 새 worker와 기존 worker가 동일 작업을 함께 claim하지 않게 하며 전환 중 재시작도 복구한다.
