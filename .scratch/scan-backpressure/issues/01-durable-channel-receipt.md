# 01: Bot 전달 큐와 BE 영속 수신 확인

**What to build:** Bot이 데이터를 잃지 않고 순차 전달하며, BE의 영속 저장 확인을 받으면 AI 결과를 기다리지 않고 해당 전달을 완료한다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 실시간·수동 분석과 전수검사가 재사용할 영속 수신 계약을 기존 경로 옆에 추가한다. 수신 데이터와 후속 처리 의도를 원자적으로 보존한 후 요청 ID와 수신 상태를 반환한다.
- [ ] Bot 전달 큐는 미확인 데이터만 재전송한다. 응답 유실 시 동일 식별자로 재전송하고 BE는 동일 내용을 중복 등록하지 않는다. 다른 내용의 식별자 재사용은 거절한다.
- [ ] 전수검사는 고정 상한·구간 경계·내용 검증값과 완료 선언을 보존한다. 빈 채널·누락 구간을 구분하며 수신 완료를 분석 완료나 Channel Checkpoint 전진으로 취급하지 않는다.
- [ ] Bot은 페이지 단위로 수집하고 작은 구간씩 저장 확인을 받는다. 전체 채널을 메모리에 쌓거나 전체 입력을 단일 요청으로 보내지 않는다. reply 관계와 Discussion Context 구성 의미를 보존한다.
- [ ] 이 티켓부터 요청 크기·구간 크기·총 미완료 수신 바이트·저장 여유에 유한한 기본 한도를 적용한다. 수신 가능 여부를 원자적으로 판단하고 저장 실패·디스크 부족에는 성공 확인을 반환하지 않는다. 실제 설정값과 거절 응답을 검증한다.
- [ ] 채널 전체가 허용 수신 용량보다 커서 완료 선언에 도달할 수 없는 경우 무한 대기하지 않고 용량 초과를 명시한다. 이미 확인한 데이터와 검사 경계는 보존하며 한도 조정 후 동일 검사에서 이어받을 수 있다. 조치 전 반복 자동 재시도로 디스크·요청량을 소모하지 않는다.
- [ ] 가상 느린 AI와 격리 DB에서 AI 완료 전 수신 확인이 반환되고, Bot/BE 재시작·응답 유실에도 데이터와 처리 의도가 보존됨을 검증한다.
