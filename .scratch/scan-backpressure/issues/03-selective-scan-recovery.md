# 03: 전달 재전송과 분석 재시도의 책임 분리

**What to build:** 전달 실패는 Bot에서, 수신 후 분석 실패는 BE에서 복구하며 필요한 데이터만 다시 요청한다.

**Blocked by:** 02 — BE 분석 큐와 독립 worker 복구

**Status:** ready-for-agent

- [ ] BE 저장 확인 전에는 Bot이 같은 데이터·식별자로 전달을 재시도하고, 확인 이후 AI 실패만으로 원문을 다시 수집·전송하지 않는다.
- [ ] BE가 누락·검증 실패 구간에만 식별 가능한 재전송 지시를 내린다. 유효한 구간을 덮어쓰지 않으며 Bot에 필요한 복구 정보는 확인 전 삭제하지 않는다.
- [ ] BE 분석 큐는 저장 입력과 workflow로 유한 지수 백오프·jitter 재시도를 수행하고 유효한 Retry-After를 존중한다. 대기 중에는 실행 슬롯을 점유하지 않는다.
- [ ] 재시도 소진 실패와 원본을 보존하고 웹 수동 재시도를 연결한다. 명시적 재분석은 전달 재시도와 별도 식별자를 사용한다.
- [ ] 재시작·응답 유실·중복 지시·AI 실패·원문 누락 fixture로 두 큐의 책임과 삭제·보관 시점을 검증한다.
