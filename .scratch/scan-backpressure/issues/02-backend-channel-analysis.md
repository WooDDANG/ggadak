# 02: BE 분석 큐와 독립 worker 복구

**What to build:** BE가 받은 데이터를 영속 분석 큐에서 처리하고, Bot 연결이나 HTTP 응답 수명과 무관하게 분석을 끝낸다.

**Blocked by:** 01 — Bot 전달 큐와 BE 영속 수신 확인

**Status:** ready-for-agent

- [ ] 실시간·수동 입력은 영속 수신 후 분석 가능해지고, 전수검사는 채널 전체 수신·완전성 확인 이후 구간별 분석 가능해진다. 일부 수신만으로 전수검사 분석을 시작하지 않는다.
- [ ] 큐에서 작업을 선택하는 worker는 기존 Analysis Request 입력·workflow·멱등 완료 결과를 재사용한다. 대기·분석 중·재시도 대기·완료·보관 실패를 구분한다.
- [ ] 재시작 후 미완료 작업을 복구하고 lease·owner 검증으로 오래된 worker의 결과 반영을 막는다. 작업 claim·AI 호출·최종 저장 간 충돌도 테스트한다.
- [ ] 결과와 후속 알림 의도를 영속 보관한다. Bot이 끊겨 있어도 분석을 진행하고 완료 상태는 재조회 가능하다.
- [ ] 이 티켓부터 전체 분석 동시 실행의 유한한 기본값 1과 채널별 직렬 실행을 적용한다. 여러 worker의 claim에서도 전체 한도를 지키며 worker 장애 후 슬롯을 복구한다. 이후 우선순위·과부하 티켓을 기다려야만 기본 제한이 적용되는 상태를 만들지 않는다.
- [ ] 요청 식별자로 감지/수집·전달 시도·BE 수신·큐 등록·분석 시작/종료·결과 반영 시간을 연결할 수 있게 한다. 전달 대기·분석 대기·AI 실행·결과 반영 지연과 두 큐의 건수·바이트를 운영 중 확인할 수 있다. 재시도별 기록을 구분하고 서로 다른 장비 시계로 측정한 지연은 오차를 명시하며, 원문·인증 값은 지표에 포함하지 않는다.
- [ ] 격리 DB·fake AI로 수신 확인 이후 비동기 실행, Bot 단절, BE 재시작, 중복 claim과 구간 경계·체크포인트 보장을 검증한다.
