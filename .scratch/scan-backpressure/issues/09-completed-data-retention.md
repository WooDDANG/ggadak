# 09: 완료 데이터 정리와 복구 기록 보존

**What to build:** Bot과 BE가 완료된 불필요한 원문·전달 자료를 제한된 양씩 정리해 저장 공간을 회수하면서, 실패 복구·결과 반영·중복 방지에 필요한 기록은 유지한다.

**Blocked by:** 05 — BE 분석 한도·우선순위와 전송량 제어; 07 — 분석 결과의 독립 처리와 Discord 요약 안내; 08 — 변경 중심 체크포인트 복구

**Status:** ready-for-agent

- [ ] Bot의 미확인 전달 원문, 확인된 전달 원문, BE의 미완료 분석 입력, 완료 입력, 결과 반영 대기, 복구용 manifest와 중복 방지 기록의 정리 가능 조건을 각각 정한다. 확인된 원문 정리도 다른 미확인 범위의 재전송·reply 구성에 필요한 자료를 제거하지 않는다.
- [ ] 정리는 설정 가능한 보존 기간과 작은 단위로 수행한다. 미완료·재시도·보관 실패 입력, 미확인 결과와 체크포인트 공백 복구 자료는 자동 삭제하지 않는다. 용량이 부족하다는 이유로 보존 의무가 있는 자료를 삭제하지 않고 수신 제어와 연결한다.
- [ ] 원문이 정리돼도 늦은 재전송을 같은 요청으로 식별하고 완료 결과나 처리 종료 상태를 반환할 최소 기록을 유지한다. 중복 방지 기록은 자동 만료시키지 않는 초기 정책으로 구현하고, 결과 보존 기간을 넘긴 요청도 새 AI 작업으로 되살리지 않는다.
- [ ] 확정 Decision Record·근거·사용자 검토 이력과 분석 입력 정리를 구분한다. 조회·명시적 재분석 기능이 필요로 하는 입력은 그 기능의 보존 계약을 확인하기 전 삭제하지 않는다. 웹에서는 입력 보존 여부와 재시도 가능성을 사실대로 표시한다.
- [ ] Bot/BE의 전체 사용량과 정리 회수량을 운영 중 확인할 수 있고, 실제 물리 저장 여유를 기준으로 수신 가능량을 판단한다. SQLite 논리 삭제만으로 파일 크기가 즉시 감소한다고 가정하지 않는다.
- [ ] 정리·결과 확인·재시도·체크포인트 갱신의 경합과 정리 중 재시작에서도 누락이나 작업 재생성이 없고 여러 번 실행해도 안전한지 격리 DB·journal 테스트로 검증한다.
