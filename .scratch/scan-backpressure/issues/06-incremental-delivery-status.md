# 06: 상태 변경분 전달과 결과 재조회

**What to build:** Bot과 웹이 변경된 상태만 동기화하고, BE에 보관된 결과를 재조회할 수 있게 하면서 완료 이력 전체의 반복 저장을 줄인다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 기존 전달 상태 동기화를 변경분·영속 확인 방식으로 바꾼다. 초기·복구 동기화는 제한된 크기로 나누고 변경 없는 완료 항목을 반복 upsert하지 않는다.
- [ ] 확인 전 변경과 전송 중 새 변경을 보존하며 중복·응답 유실·순서 뒤바뀜·재시작을 처리한다.
- [ ] 생존 확인을 가볍게 유지해 기존 15초 신선도 계약을 지킨다. 연결 여부와 수신·분석 상태를 구분한다.
- [ ] BE 보관 결과를 요청 식별자와 변경 위치 기준으로 제한된 크기로 재조회할 수 있는 계약을 제공한다. 기존 결과부터 독립 적용 가능하고 새 분석 worker도 같은 계약에 연결할 수 있다.
- [ ] Bot·BE·웹·생성 API 계약과 수동 재시도 command의 멱등 전달을 함께 맞춘다. SSE/WebSocket 도입은 확정하지 않고 전송 방식과 무관하게 재조회·확인 계약을 유지한다.
- [ ] 격리 DB·가상 시간에서 유휴 갱신 수·재연결·많은 이력·웹 표시·결과 재조회와 재시도 명령을 검증한다.
