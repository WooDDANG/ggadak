# 10: 분리된 두 큐의 부하·복구 통합 검증

**What to build:** 전수검사 중 Bot 전달과 BE 분석이 병행되고, 느린 AI·재시작·과부하에서도 데이터와 서비스 응답성이 유지됨을 검증한다.

**Blocked by:** 09 — 완료 데이터 정리와 복구 기록 보존 (각 선행 티켓의 의존성 포함)

**Status:** ready-for-agent

- [ ] 대형 채널·많은 완료 이력·동시 실시간 요청·느린 AI·Bot/BE 재시작·누락 구간·채널 실패를 함께 재현하는 fixture를 제공한다.
- [ ] Bot 미확인 전달 수와 BE 대기 분석 수를 별도로 측정한다. 최대 보유 메시지·보관 입력 바이트·분석 동시 수·대기 시간·Discord/BE 요청 수·DB 갱신·로그인/조회 지연과 오류를 기록한다.
- [ ] AI 응답 대기 없이 데이터 전달이 진행되고 BE 수신 용량에 맞춰 멈춤·재개하는지 확인한다. 큐·디스크 사용이 무제한 증가하지 않아야 한다.
- [ ] 수신 확인 후 Bot 전달을 완료해도 분석 입력이 남고, 응답 유실·재연결·결과 중복에도 데이터 유실·중복 분석·체크포인트 선행이 없음을 확인한다.
- [ ] 웹과 Discord가 전달 완료·분석 완료·대기·실패·오프라인을 구분한다. 실시간 우선 처리 중에도 전수검사가 진행한다.
- [ ] 운영 한도·보관 입력 정리·기존 작업 전환·복구 절차·관련 ADR 구현 상태를 문서화한다. 실제 Discord 전송·유료 AI 호출은 별도 승인 없이 하지 않는다.
- [ ] 채널 전체 크기가 수신 한도보다 큰 fixture에서 수신·분석이 서로 기다리는 교착이 없고, 명시적 용량 초과·한도 조정 후 재개가 동작함을 검증한다. 디스크 부족은 허위 수신 확인이나 자동 삭제로 숨기지 않는다.
- [ ] 운영 지표에서 전달 대기·분석 대기·AI 실행·결과 반영 지연을 각각 확인하고, 알려진 지연을 주입해 병목 단계가 정확히 식별되는지 검증한다.
- [ ] BE 완료 후 Bot 응답 유실, 기존 분석 실행 중 큐 전환, 전환 직후 재시작을 포함해 결과 중복 저장·불필요한 AI 재호출·이중 worker·데이터 유실이 없는지 검증한다. 외부 AI 완료 직후 결과 영속화 전 장애처럼 중복 호출을 완전히 막을 수 없는 구간은 구분해 기록한다.
- [ ] 정리 작업 중 재시작·재조회·늦은 재전송을 함께 실행해 필요한 입력·결과·중복 방지 기록이 남고, 삭제된 완료 데이터가 다시 작업으로 생성되지 않음을 검증한다.
