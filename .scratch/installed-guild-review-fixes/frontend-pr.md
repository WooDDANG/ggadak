## 변경 내용

Discord 로그인 응답의 검증된 서버 목록을 사용하고, 가입 서버 중 GGADDAK 봇이 설치된 서버만 선택합니다. 새로고침 시 HttpOnly 쿠키로 세션을 복원하며, 서버 목록 확인 실패는 정상 빈 목록과 구분합니다.

```text
로그인·세션 복원
  → BE가 반환한 설치 확인된 가입 서버 목록 사용
  → 확인 불가: 로그인 유지·데이터 숨김·재확인
  → 정상 빈 목록: 설치된 가입 서버 없음 안내
  → 정상 목록: 유효한 선택 유지·제거된 선택 교체
```

포커스 복귀·온라인 복귀·수동 요청으로 목록을 재확인합니다. 같은 계정·적격 서버의 카드 편집과 채널 선택 초안은 유지하고, 확인 중인 화면은 숨김·inert 상태로 조작과 데이터 요청을 차단합니다. 계정·서버 접근 범위가 바뀌면 이전 화면을 정리합니다.

인증 취소 후 처음 화면으로 돌아가면 기존 쿠키 세션을 복원하거나 로그인 화면을 표시합니다. 예약 JWT 갱신과 401 복구는 같은 진행 중인 요청을 공유하며, 조회만 한 번 재시도하고 변경 요청은 재전송하지 않습니다. JWT 갱신에 따른 주기적 서버 목록 조회는 없습니다. FE 작업은 작업 브랜치와 PR로만 진행하도록 지침도 추가했습니다.

## 검증

- 변경 전: 포커스 복귀 시 저장 전 초안이 사라지고, Discord 인증 취소 후 처음 화면으로 돌아가면 무한 로딩했습니다. 예약 갱신·401 복구 경합에서 토큰 요청이 2회 발생했습니다.
- 변경 후: 실제 화면의 초안 유지·확인 불가 차단/복구·접근 범위 변경 시 제거·인증 취소 복귀가 동작하고, 갱신 경합은 요청 1회를 공유합니다. 로그인 응답도 재사용해 불필요한 후속 조회를 줄입니다.
- FE 검증: `npm test`와 `npm run build`. Chrome 화면·HTTP 경합 회귀 12개를 실행합니다. 테스트 파일은 공유 Vite 캐시 충돌을 피하도록 직렬 실행합니다.
- 부모 저장소 검증: `npm run typecheck`, `npm test`. 실제 FE→BE 브라우저 4개가 실제 OAuth state·HttpOnly 쿠키·목록·데이터 인가·이벤트·JWT 경로를 통과합니다. 실제 예약 갱신에 401 조회 3개를 겹쳐 토큰 요청 1회·각 조회 재시도 1회를 확인합니다.
- 최종 전체 검증 통과: BE 184개, Bot 53개, FE 12개, E2E 13개. 타입 검사와 전체 빌드도 통과했습니다.
- Discord의 실제 봇 제거·재설치 조작은 자동화하지 않았으며, 외부 응답과 이벤트는 테스트 fixture로 제어했습니다.
