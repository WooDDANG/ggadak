# 04: 실제 FE→BE 인증·서버 선택·복구 회귀 검증

**What to build:** 실제 FE 화면을 실제 BE HTTP 서버에 연결해 로그인, 설치된 가입 서버 선택과 리뷰 수정 사항이 함께 동작함을 검증한다. 브라우저가 받는 BE 인증·목록 응답을 별도 성공 응답으로 대체하지 않는다.

**Blocked by:** 01: 포커스 복귀와 서버 재확인 시 편집 초안 보존; 02: Discord 인증 취소 후 정상 화면 복귀; 03: JWT 예약 갱신과 401 복구의 동시성 정책 통합.

**Status:** ready-for-agent

- [x] 격리된 실제 BE HTTP 서버와 테스트 저장소에 실제 FE를 연결하고, 외부 Discord 가입·설치 관측만 제어한다. 사용자 인증, 세션, 서버 목록, 쿠키·Origin 검사와 데이터 인가 경로는 실제 BE 구현을 통과한다.
- [x] 실제 화면에서 OAuth 로그인·HttpOnly 쿠키 세션 복원·명시적 서버 재확인이 같은 설치된 가입 서버 목록을 사용함을 확인한다. 일반 멤버와 저장된 카드·모니터링 채널이 없는 적격 서버도 포함한다.
- [x] 정상 빈 목록과 설치 확인 불가를 구분하고, 확인 불가 시 기존 서버 데이터를 차단하면서 로그인을 유지한 뒤 재확인으로 복구한다.
- [x] 제어된 봇 제거·재설치·사용자 탈퇴 이벤트를 실제 BE 수신 경계에 전달하고, 포커스 복귀·수동 재확인 후 목록·선택·인가가 갱신됨을 확인한다.
- [x] 실제 편집 화면의 초안 보존, 인증 취소 후 정상 복귀, 계정·서버 전환 후 이전 응답 차단을 검증한다.
- [x] 실제 BE 토큰 경로를 통해 만료 토큰 복구·예약 갱신 경합·안전한 조회 한 번 재시도·변경 요청 자동 재전송 금지를 검증하며 idle 상태의 설치 목록 주기 조회가 없음을 확인한다.
- [x] 테스트는 운영 DB·실제 Discord 서버·개인 자격증명을 변경하지 않는다. 테스트 프로세스·저장소·브라우저 프로필은 종료 시 정리하고 토큰이나 쿠키 원문을 출력하지 않는다.
- [x] Herdr 검증 pane에서 실행할 재현 가능한 명령과 결과를 문서·한글 PR에 기록한다. 제어된 외부 관측과 실제 Discord 수동 검증 범위를 구분한다.
- [x] 검증한 FE 커밋과 부모 저장소의 submodule 포인터를 일치시키고, FE PR 병합 대기 여부를 명시한다. 기본 브랜치 직접 push나 자동 merge를 하지 않는다.
