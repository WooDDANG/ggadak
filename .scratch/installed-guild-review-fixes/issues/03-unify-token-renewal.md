# 03: JWT 예약 갱신과 401 복구의 동시성 정책 통합

**What to build:** 예약된 JWT 갱신과 실제 API의 401 복구가 겹쳐도 같은 계정의 갱신 요청을 공유하고, 세션·계정 전환 정책이 동일하게 동작하도록 한다. 사용자가 제출한 변경 요청은 자동으로 반복하지 않는다.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 같은 인증 범위에서 예약 갱신과 여러 API의 401 복구가 겹치면 하나의 진행 중인 JWT 갱신 요청을 공유한다.
- [x] 갱신 결과의 계정 식별·토큰 저장·실패 처리를 공통 정책으로 적용하며, 이전 계정 또는 무효화된 범위의 늦은 갱신 결과가 현재 토큰을 덮어쓰지 않는다.
- [x] 갱신 결과가 다른 계정이면 기존 화면을 차단하고 쿠키 세션을 다시 확인한 뒤 해당 계정 상태를 구성한다.
- [x] 안전한 조회 요청은 갱신 성공 후 최대 한 번만 재시도한다. 변경 요청은 갱신과 무관하게 자동 재전송하지 않고 원래 실패를 호출자에게 전달한다.
- [x] 일시적인 갱신 장애로 지속 쿠키를 폐기하지 않으며, 세션이 실제 만료된 경우에는 정상 재로그인 경로로 전환한다.
- [x] JWT 갱신만으로 가입 서버·설치 목록을 재조회하지 않으며 고정 주기의 전체 목록 조회를 도입하지 않는다.
- [x] 제어된 HTTP 경계에서 예약 갱신·401 경합, 계정 전환 중 늦은 응답, 일시 장애, 조회 재시도 횟수와 변경 요청 중복 방지를 검증한다.
- [x] FE 작업은 작업 브랜치와 PR로 제출하며 PR 제목·본문은 한글로 작성한다. 빌드와 테스트는 Herdr 검증 pane에서 실행한다.
