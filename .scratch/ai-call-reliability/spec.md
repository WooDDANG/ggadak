# AI 호출 신뢰성

2026-11-19 AI 경로 점검에서 나온 항목 중, 진행 중인 `degraded-analysis-recovery`·`graph-repair-reliability` 작업과 겹치지 않는 것을 모았다.

## 결정

- 호출 타임아웃은 `AI_CALL_TIMEOUT_MS`로 정하고 기본값은 60초, 출력 상한 기본값은 8,192토큰이다. 세션 시간 예산은 300초(논리 호출 5회 × 60초)로 늘리고, Bot의 동기 전달 마감도 310초로 맞춘다.
- 실패 분류는 던지는 쪽이 지정한 코드로 정한다. **출력 형식 실패**는 구조·의미 검증 실패와 별개 범주다.
- 출력 형식 실패와 타임아웃은 세션 건너뜀 대상이고, 잘린 응답은 자동 재시도하지 않는다. 소유권 상실은 실패가 아니다(ADR-0028).
- 403은 1시간 cooldown, 401은 영구 비활성화다. 남은 키가 모두 403으로 쉬면 인증 장애로 알린다.
- 큐 전체 정지는 provider 5xx, 모든 키의 인증·권한 실패, DB 장애에만 둔다. 코드별 처리는 `issues/02`의 표를 따른다.
- 세션 시간·논리 호출 예산 소진도 세션 건너뜀 대상이다. 복구 기록은 가장 최근 실패의 종류를 보존한다.
- Verify 모델 분리는 측정 후 결정한다.

## 다른 곳에서 처리하는 항목

- 실패 테스트 4건, 손상 기록 requestId: `degraded-analysis-recovery/01`
- 건너뜀 범위 확대, 큐 전체 정지 조건: `degraded-analysis-recovery/02`
- 재시도별 seed, 잘림 재시도 제외: `degraded-analysis-recovery/03`
- 로그의 원문 제거: `graph-repair-reliability/05`

## 하지 않는 항목

- 메시지 역할 분리(system/user): 사람 검토 단계가 있어 현재 위험이 낮다.
- `AI_MAX_INPUT_CHARS` 기본 제한: 세션 분할이 상한 역할을 한다.
- 워크플로 안의 즉시 재호출: ADR-0025의 숨은 재시도 금지를 유지한다.
- provider 전체 장애 감지: 필요해지면 연속 실패 횟수 기준으로 따로 넣는다.
