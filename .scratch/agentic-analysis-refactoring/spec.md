# AI 에이전틱 분석 실행·게시·조회 책임 분리

2026-10-24 코드 검토 후 사용자의 `$implement` 요청으로 진행한다.

## 요구사항

- 분석 요청과 실행 슬롯을 획득한 뒤 체크포인트 조회·복원·전처리·분석·게시 어느 단계에서 실패하더라도 실행 자원을 정리한다. 복원 실패 직후 다른 분석이 lease 만료를 기다리지 않고 실행될 수 있어야 한다.
- 실행권, heartbeat, 취소, 실패 기록, 정리를 하나의 실행 모듈이 관리한다. 소유권 fencing, 같은 채널 직렬화, 세션 병렬 처리, AI 호출 전역 상한은 보존한다.
- 실행과 Analysis Queue가 같은 재시도 분류를 사용한다. 실행 용량 경합은 명시적 오류 타입으로 구별하며 오류 메시지 내용으로 attempt 차감 여부를 판단하지 않는다. 기존 HTTP 상태와 retry-after 동작을 보존한다.
- 그래프의 Decision Candidate 변환과 후보 게시 정책을 실행 orchestration 및 저장 쿼리에서 분리한다. 기존 동일성, 거절 억제, 수동 재분석, 검수 변경 보존, 레거시 호환과 이력을 유지한다.
- 관련 후보 탐색은 한 번의 게시 안에서 같은 채널의 전체 identity를 후보마다 반복 조회·파싱하지 않는다. 같은 게시에서 새로 생성한 후보의 관련 이력도 보존한다.
- 후보·관련 이력·그래프·최종 결과는 소유권을 확인한 동일 트랜잭션에서 게시하며, 일부 저장 실패 시 전부 rollback한다.
- guild 범위 상태·그래프 조회는 AI 실행 모듈에 의존하지 않는다. 기존 API 응답과 그래프의 현재 Decision 버전 표시를 유지한다.

## 검증

- 복원 실패 이후 다음 분석의 즉시 성공, 용량과 유사한 메시지를 가진 provider 오류의 attempt 차감에 대한 회귀 검증.
- 기존 분석 API, 세션 복구·병렬 실행·전역 호출 제한, 거절·수동 재분석·검수 보존·이력·저장 rollback 테스트 유지.
- 타입 검사, 변경 파일 lint/format, 전체 테스트, Standards/Spec 두 축 리뷰.

## 범위

AGY 생성 경로, 추출·검증·최대 1회 수정 알고리즘, 기존 API 계약과 저장 스키마를 유지한다. 운영 DB 마이그레이션이나 실제 AI 계정의 처리량 조정은 포함하지 않는다.
