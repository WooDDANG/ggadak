# BE 저장 모델 정리와 세션 병렬 처리

Status: implemented — 로컬 구현·검증 기준. 운영 DB 적용·복원 검증과 실제 AGY 측정에 따른 운영 N 선정은 미완료. 변경 근거·검증 결과·남은 조건은 [구현 검증 기록](implementation-verification.md) 참조

## 목적

SQLite와 Prisma를 유지하면서 사용하지 않는 컬럼, 중복 저장 기준, 잘못된 필드 의미와 반복 조회를 정리한다. 안전한 체크포인트 위에서 설정 가능한 N개의 독립 세션을 병렬 처리하고, 적정 N을 측정으로 선택한다. 결정 조회·검수·분석 복구·중복 방지 계약을 보존한다.

## 확인한 상태

2026-10-17 로컬 DB 읽기 전용 점검 기준:

- Decision 341개 중 domainJson이 있는 행은 36개, 없는 레거시 행은 305개다. 검사한 JSON/컬럼 상태 불일치와 주요 후보·분석·검수 참조 누락은 0건이다.
- 최신 Analysis Queue 마이그레이션이 미적용되어 코드의 수신·스캔·실행 테이블과 실제 DB가 다르다.
- archivedAt은 애플리케이션의 읽기·쓰기 경로가 없고 현재 모든 값이 NULL이다. configJson은 기록만 하며 workflow 설정과 중복된다. 거절 근거 사유는 현재 고정값으로만 기록한다.
- External Feedback은 채널 중심 도메인인데 이전 decisionId에 채널 ID를, author에 source를 기록한다. 현재 로컬 피드백 행은 없지만 API·저장 경로는 사용 중이다.
- 후보 이력의 역방향 관련 후보 탐색은 전체 행을 반복 조회한다. 그래프 조회는 연결된 Decision을 하나씩 조회한다.

## 범위와 원칙

- 읽기용 컬럼은 조회 목적의 파생값으로 유지할 수 있으나, 도메인 원본과 일관되게 갱신해야 한다.
- 레거시 필드와 읽기 경로는 새 형식 추가·이관·대조 검증 후 제거한다. 누락된 과거 정보는 만들어내지 않는다.
- 분석 당시 그래프와 인간 검수 이력은 보존한다. 그래프 snapshot 전체를 노드/간선 테이블로 정규화하는 요구는 없다.
- 운영 DB 변경은 선택한 DB·백업·복구 경로가 구체적으로 확인된 실행 단계에서 수행한다. 개발/자동 테스트는 격리된 DB 복사본을 사용한다.
- 로컬 DB의 현재 데이터 개수나 NULL 분포를 다른 환경에 그대로 가정하지 않는다.

## 세션 병렬 처리

- 2개를 고정값으로 사용하지 않는다. 서비스 전체의 동시 AI 호출 상한과 요청별 세션 worker 수를 설정으로 구분하며, 기본값 1에서 기존 순차 동작을 보존한다.
- 요청별 N이 요청 수만큼 곱해져 전역 한도를 넘지 않게 한다. 동일 DB를 공유하는 BE 프로세스와 분석 경로는 같은 AI 호출 한도를 따른다.
- 독립 세션을 병렬 실행하되 각 세션 내부의 추출·검사·검증·수정 순서와 예산은 유지한다. 같은 채널의 서로 다른 분석 요청은 기존 직렬화 계약을 유지한다.
- N은 같은 모델·입력 분포·환경에서 순차 기준선과 비교해 선택한다. 정상 완료 처리량, 대기/완료 지연, 할당량·timeout·출력 실패, CLI 메모리/CPU, DB 쓰기 경합과 로그인/조회 지연을 함께 측정한다.
- 권장 N은 측정한 지연·오류·자원 한도를 만족하면서 처리량 증가가 둔화되기 전의 값으로 결정한다. 고정된 보편 최적값이나 fixture 결과만으로 실제 AGY 계정의 적정 N을 주장하지 않는다. 자동 동적 증감은 이번 범위가 아니다.

## 기존 작업과의 경계

Bot 전송 상태와 BE 수신·분석 상태는 책임이 다르므로 유지한다. BE 수신 후 분석은 BE가 책임지며, 웹은 BE가 소유한 상태를 우선한다. 완료된 전송 사본의 보존·정리와 늦은 재전송 처리는 기존 [완료 데이터 정리와 복구 기록 보존](../scan-backpressure/issues/09-completed-data-retention.md)을 사용한다. 전달·분석 대기 지표와 재시작/정리 경합 검증은 기존 [부하·복구 통합 검증](../scan-backpressure/issues/10-scan-load-verification.md)에 연결한다. 기존 티켓은 수정하지 않는다.
