# 11: 설정 가능한 N개 세션 병렬 처리

**What to build:** 한 분석 요청에 포함된 독립 대화 세션을 설정 가능한 N개 worker로 처리해 순차 실행의 대기 시간을 줄이면서, 최종 결과와 재시작 복구를 보존한다.

**Blocked by:** 09 — 분석 원본과 실행 체크포인트 분리; 10 — 서비스 전체 AI 호출 동시 실행 한도.

**Status:** resolved

- [x] 요청별 세션 worker 수 N을 양의 정수 설정으로 제공하고 기본값 1에서 기존 동작을 유지한다. 무제한 Promise.all 대신 제한된 worker를 사용한다.
- [x] 각 세션은 기존 추출·구조 검사·AI 검증·필요 시 수정 순서, 모델 설정, 시간/수정 예산을 유지한다.
- [x] 여러 세션과 다른 요청이 경쟁해도 전역 AI 호출 상한을 따르며, 요청 수와 worker 수의 곱으로 CLI 실행 수가 무제한 증가하지 않는다.
- [x] 세션별 checkpoint와 ID 매핑이 서로 덮어쓰이지 않고, 완료 순서가 달라도 최종 snapshot과 후보 순서는 기존 세션 순서를 따른다.
- [x] 한 세션 실패나 요청 소유권 상실 시 추가 작업 시작을 중단하고 실행 중인 형제 작업의 취소·종료·checkpoint 완료를 기다린다. 모든 세션이 검증되기 전 후보를 부분 공개하지 않는다.
- [x] 재시작/재시도는 저장된 성공 세션과 중간 단계를 재사용한다. 같은 채널의 다른 요청 직렬화와 중복 공개 방지를 보존한다.
- [x] 지연이 다른 세션으로 실제 겹친 실행과 N 상한을 확인하고, 순차/병렬 결과 동등성·동시 저장·형제 실패·응답 유실·재시작을 fixture와 격리 DB로 검증한다.

## Answer

AI_SESSION_CONCURRENCY로 요청별 worker 수, AI_CALL_CONCURRENCY로 전역 호출 상한을 구분했다(각 기본 1, 허용 1..32). stage 순서/수정 예산/결과 순서/최종 원자 commit을 보존하고 실패 시 형제 작업을 취소한 뒤 완료 checkpoint로 재개한다.
