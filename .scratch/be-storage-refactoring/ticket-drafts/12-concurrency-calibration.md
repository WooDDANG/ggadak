# 12: 병렬 수 N의 측정과 운영값 선정

**What to build:** 운영자가 N을 추측으로 정하지 않고, 동일 조건의 측정 결과에서 서비스 지연·오류·자원 예산을 만족하는 병렬 수를 선택할 수 있게 한다.

**Blocked by:** 11 — 설정 가능한 N개 세션 병렬 처리.

**Status:** needs-triage

- [ ] N=1 기준선과 사용자가 지정한 여러 N을 같은 입력·모델·환경·예산으로 비교하는 재현 가능한 측정 명령과 보고서를 제공한다. 요청별 worker 수와 전역 호출 상한을 모두 기록한다.
- [ ] 짧은/긴 세션과 토큰량 차이, 수정 발생, 여러 요청의 경합을 포함한다. 정상 완료 세션 처리량, AI 슬롯 대기, 전체 완료 p50/p95, quota/timeout/검증 오류, CLI 메모리·CPU와 DB 경합을 기록한다.
- [ ] 로그인/조회 지연 등 미리 명시한 운영 한도와 자원 여유를 만족하는 후보만 비교하고, 처리량 증가가 둔화되거나 오류·지연이 악화되는 구간을 보고한다. 측정 범위를 넘는 최적 N을 단정하지 않는다.
- [ ] fixture 측정과 실제 AGY 측정을 명확히 구분한다. 실제 측정은 대상 계정·모델·환경과 명시한 호출/토큰/시간 예산 아래 별도로 실행하며 일반 테스트는 외부 AI를 호출하지 않는다.
- [ ] 모델·계정 한도·배포 자원이 바뀌면 재측정할 조건, 선택한 N의 근거와 한계, N=1로 복귀하는 절차를 문서화한다. 자동 동적 증감은 포함하지 않는다.
- [ ] 기존 전달·분석 부하/복구 검증과 지표 의미를 맞추며 동일한 통합 부하 티켓을 중복 생성하지 않는다.
