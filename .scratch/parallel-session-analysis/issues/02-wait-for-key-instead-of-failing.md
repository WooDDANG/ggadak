# 02: 빈 NVIDIA 키가 없으면 요청을 실패시키지 않고 잠깐 기다렸다 다시 시도한다

**What to build:** AI 호출 차례를 받았는데 키 풀에 바로 쓸 키가 없으면(다른 키가 429 cooldown 중이거나, 403으로 쉬거나, 끝난 프로세스가 아직 잠금을 쥐고 있음), 호출 차례를 쥔 채 키가 풀릴 때까지 기다린 뒤 호출한다. 지금은 즉시 "용량 대기" 오류가 나서 세션 단위 실패가 아니므로 형제 세션까지 중단되고 분석 요청 전체가 다시 시작된다. 이미 쓴 토큰도 버려진다.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 짧게 기다리면 쓸 수 있는 키가 생기는 경우, 호출은 실패하지 않고 그 키로 진행된다
- [x] 키를 기다린 시간은 지금처럼 AI 호출 제한(30초)과 세션 시간 예산에 들어가지 않는다
- [x] 30초 안에 풀리지 않는 대기(분당 예산 소진, 429·403 cooldown)는 지금처럼 큐 대기로 넘기고 무한정 붙잡지 않는다
- [x] 키 두 개가 쉬는 동안 세션 셋이 실패 없이 끝나는 것을 테스트로 보인다

## Comments

2026-11-19 동시 처리 3 코드 검토에서 확인했다. 키 4개 중 1개를 예비로 두므로 빈도는 낮지만 429가 몰리면 발생한다.

2026-11-19 구현: 키 대기 상한은 30초다. 다른 호출이 쥔 키는 호출 제한 시간 안에 풀리므로 그만큼 기다리고, 분당 예산 소진·429·403 cooldown처럼 더 오래 걸리는 대기는 기존처럼 큐 대기로 넘긴다(기존 '계정 예산 대기' 테스트가 이 경계를 지킨다). 기다린 시간은 세션 대기 시간(waitMs)에 더해지고 세션 시간 예산에는 들어가지 않는다.
