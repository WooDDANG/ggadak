# 01: 요청 전체 실패 시 처리 중인 세션은 끊지 않고 마무리시킨다

**What to build:** 한 분석 요청의 세션을 여러 개 동시에 처리하다가 한 세션이 요청 전체 실패(예: provider 5xx, 모든 키 인증 실패, DB 장애)를 내면, 새 세션은 더 시작하지 않되 이미 처리 중인 세션은 진행 중인 AI 호출을 끝까지 마치고 결과를 체크포인트에 저장한다. 그 뒤 요청을 재시도하면 끝난 세션은 건너뛰고 남은 세션만 이어 간다.

지금은 형제 세션의 진행 중 호출을 즉시 끊는다. 그래서 거의 끝난 호출의 결과와 토큰이 버려지고, 끊긴 호출의 경과 시간(최대 30초)이 형제 세션의 시간 예산(150초)에 더해진다. 재시작이 반복되면 스스로 실패한 적 없는 세션이 "시간 초과로 건너뜀"이 되어 복구 대상으로 남는다. 동시 처리 1에서는 형제 세션이 없어 생기지 않는다.

소유권 상실(다른 실행 주체가 요청을 넘겨받음)과 프로세스 종료는 같은 요청을 두 곳에서 처리하지 않도록 지금처럼 즉시 끊는다.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 한 세션이 요청 전체 실패를 내면 새 세션은 시작하지 않고, 처리 중인 세션은 현재 호출을 마친 뒤 결과를 저장하고 멈춘다
- [x] 마무리된 세션의 결과는 재시도에서 다시 분석하지 않는다
- [x] 다른 세션의 실패 때문에 세션 시간 예산이 줄거나 "시간 초과로 건너뜀"이 기록되는 일이 없다
- [x] 요청은 모든 처리 중 세션이 마무리된 뒤에 처음 실패의 종류로 실패·재시도된다
- [x] 소유권 상실과 종료 신호는 지금처럼 처리 중인 호출을 즉시 끊는다
- [x] 세션 셋 중 하나가 요청 전체 실패를 반복해도 나머지 둘이 완료되고 시간 예산이 보존됨을 테스트로 보인다

## Comments

2026-11-19 동시 처리 3(AI_CALL_CONCURRENCY=3, AI_SESSION_CONCURRENCY=3, ANALYSIS_CONCURRENCY=1) 코드 검토에서 형제 중단 시 끊긴 호출의 경과 시간이 세션 예산에 더해지는 버그를 찾았다. 예산 계산만 고치는 대신, 사용자 결정으로 형제 세션을 끊지 않고 마무리시키는 방식으로 바꾼다. 결과·토큰 손실도 함께 없어진다.
