# 동시 처리 3 실측

2026-11-19 14시 KST에 측정했다. 테스트 서버 대화(채널 3개, 메시지 134개, 세션 24개)를 채널마다 분석 요청 하나로 넣고, 운영 `DiscussionService`(세션 작업자, AI 호출 스케줄러, NVIDIA 키 풀, Extract → 검사 → Repair → Verify, 후보 발행)로 처리했다. 같은 입력을 동시 처리 1과 3으로 한 번씩 돌렸다.

## 조건

| 항목 | 값 |
|---|---|
| 코드 | `feat/parallel-session-drain`(main + 티켓 01·02). 프롬프트 agentic-4 |
| 모델 | `nvidia/nemotron-3.5-super-vl-120b-a12b`, 추론 끔, 출력 상한 8,192 |
| 호출 제한 | 30초 |
| 키 | 4개, 키당 분당 40회 |
| 분석 요청 동시 처리 | 1 (채널은 차례로) |
| 실행 위치 | 로컬 Mac, 임시 SQLite |

## 결과

| | 동시 처리 1 | 동시 처리 3 |
|---|---|---|
| 전체 시간 | 250초 | **126초** |
| 실제 AI 호출 | 65회 | 56회 |
| 동시에 진행된 호출 최대 | 1 | 3 (3을 넘은 적 없음) |
| 호출 시점 동시 호출 수 분포 | 1: 65 | 1: 7, 2: 10, 3: 39 |
| 키별 호출 | 16 / 17 / 16 / 16 | 18 / 9 / 11 / 18 |
| 빈 키가 없어 예약 실패 | 0 | 0 |
| 세션 최대 대기 시간 | 0.02초 | 0.04초 |
| 끝난 뒤 남은 AI 호출 임대 | 0 | 0 |
| 분석 요청 결과 | 3개 모두 완료 | 3개 모두 완료 |
| 건너뛴 세션 | 9 (의미 검증 8, 시간 초과 1) | 5 (의미 검증 4, 시간 초과 1) |

## 해석

- 동시 처리 3으로 전체 시간이 절반으로 줄었다. 호출은 최대 3개까지만 동시에 나갔고 예비 키 1개가 늘 남아, 키를 기다리거나 키가 없어 실패한 호출이 없었다.
- 동시 처리 때문에 생긴 실패는 없었다. 결과는 모든 세션이 끝난 뒤 발행됐다.
- 건너뛴 세션의 대부분은 Verify가 정상 세션을 의미 오류로 보고한 경우다. 이 브랜치에는 PR #16의 의미 검사 전용 Verify가 아직 없다. 건너뛴 수가 실행마다 다른 것은 Verify 판정이 매번 달라서이며 동시 처리와 무관하다.
- 호출 수와 건너뛴 수가 달라 두 실행의 일이 완전히 같지는 않다. 시간 단축 폭은 대략값이다.
