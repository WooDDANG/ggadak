## Question

합의 없는 제안도 제출하고 출처 없는 요약도 허용하는 목적에 맞춰 후보 누락·허위 합의·입력 밖 사실 생성·관계 오류·비용·지연을 어떻게 평가할까? 대표 대화와 기대 결과, deterministic 검증과 실제 모델 평가의 역할, 수용 기준 및 명세 인계 조건을 정한다.

실제 유료 평가 실행은 하지 않는다. 기존 AI 후속 구현 티켓의 출력 검증·인용 진위·공급자 오류·연결·품질 평가 중 유지·수정·대체할 범위를 결정한다. 사용자 합의 없이 기존 초안을 실행 티켓으로 승격하지 않는다.

## Answer

### 두 평가 층

**AMI 기반 평가**는 영어 회의의 결정 내용 추출·요약을 검증한다. 공식 scenario-only 개발 20개 회의로 prompt·설정·변환을 조정하고, 최종 비교는 공식 평가 20개 회의에서 수행한다. train 98개는 개발용 사례·few-shot 후보로만 사용하고 test 정답을 prompt나 조정에 사용하지 않는다. 나머지 4개는 별도로 보관한다. 기존 잠정 40/10 분할로 공식 분할을 대체하지 않는다.

모델에는 회의 대화만 입력한다. originalGold 요약을 입력에 포함하지 않는다. 긴 회의를 세션으로 분할하면 동일한 전처리로 두 방식을 실행하고, 회의 단위로 결과를 모아 의미 대응으로 비교한다. 결정 누락·왜곡·입력에 없는 이유 생성 등을 확인한다. 694개 요약 중 발화 연결이 있는 624개와 연결 없는 70개를 구별하며 연결 기반 지표에는 확인 가능한 항목만 사용한다.

AMI 요약은 모든 미합의 제안을 포함한 정답이 아니다. 요약에 없는 제안을 즉시 오탐으로 판단하지 않고, AMI의 결정 요약 기반 결과와 서비스 후보/그래프 결과를 별도로 보고한다. AMI 통과만으로 한국어 Discord 목표 달성을 주장하지 않는다.

**서비스 평가**는 미합의 제안·경쟁 대안·철회·근거 없음·문제/질문만 있음·여러 선택·실제 대화 모순을 포함한 완전 주석 구간에서 수행한다. 한국어 실제 대화/회의록 및 사용 가능한 공개 주석에 우리 후보·관계 계약의 추가 정답을 만든다. 초기 50개는 목표 규모이며 확보 상황과 독립 원문 회의 수를 확인해 확정한다. 규모가 작다고 AMI와 합쳐 단일 정확도로 제시하지 않는다.

### 정답 작성과 의미 대응

AI가 정답 초안을 도울 수 있으나 사람이 입력 대화를 읽고 최종 검수한다. 후보 묶음·대안·관측·이력·근거·후속 활동·관계의 완전성을 확인한다. 언급되지 않은 근거·담당자·기한은 빈 값으로 남기고 평가 모델의 출력에 맞춰 test 정답을 바꾸지 않는다. 정답은 분석 모델과 독립적으로 버전·출처·검수 여부를 기록한다.

후보와 관계를 먼저 의미적으로 일대일 대응시켜 TP/FP/FN을 계산한다. 표현 차이를 오류로 간주하지 않으며, 같은 선택을 여러 후보로 잘못 쪼갠 결과나 중복 출력은 중복 정답으로 인정하지 않는다. 관계는 대응된 노드의 끝점과 관계 의미로 판단하며 BE 발급 ID 문자값을 정답과 일치시키지 않는다. 인간 검수된 대응이 초기 기준이며 AI judge 점수만으로 합격 판정하지 않는다.

### 품질 목표와 적용 범위

초기 목표는 완전 주석된 서비스 평가셋에서 다음과 같다.

- 허위 합의, 입력 밖 근거·담당자·기한 생성 0건.
- 후보 정밀도·재현율 및 관계 정밀도·재현율 각각 90% 이상.
- 검수에 제출한 그래프 구조 오류 0건.

분모와 지표 계산이 불가능한 항목은 100%로 채우지 않고 N/A로 보고한다. 기존 AMI 요약만으로 후보 전체·그래프 재현율을 계산하지 않는다. 실패·예산 소진·무결정·맥락만 존재를 구별하고 실패 요청을 평가 대상에서 숨기지 않는다. 위 목표는 해당 평가셋의 수용 기준이며 모든 실제 대화에 대한 보장은 아니다.

한국어 평가 준비 전에도 명세·구현·고정 응답 테스트를 진행할 수 있다. 한국어 gold 미확보는 알려진 검증 공백이며 서비스 한국어 품질 합격은 해당 평가 완료까지 보류한다. 출처·번역 여부·분할을 기록하고 번역 AMI를 실제 한국어 대화와 동일한 자료로 집계하지 않는다.

### 비교와 운영 예산

기존 단일 호출과 새 고정 workflow를 동일 입력·분할·공급자/모델 설정에서 비교한다. 모델 ID·설정·prompt 버전·출력 한도·원본 checksum·정답 버전을 실행 manifest에 고정한다. 비용 비교 중 모델을 바꿔 workflow 효과와 섞지 않는다. 공급자는 기존 Adapter 경계를 유지하며 특정 모델 교체를 이번 설계의 선행 조건으로 삼지 않는다.

호출 수, 실제 통신 시도, 단계별 토큰·지연, 수정 빈도·수정 성공률, 최종 실패율을 함께 측정한다. 세션 180초·호출 45초·수정 한 번의 합의된 상한은 유지한다. 정량적인 토큰 상한·금액 상한은 실측 없이 최적값을 정하지 않는다. runner는 실행 전에 지원 모델에 맞는 명시적 입력/출력 및 총 호출·토큰/금액 예산을 설정하도록 하고, 예산 없는 유료 배치 실행을 하지 않는다. 한도 초과 시 조용히 잘라 성공 처리하지 않는다.

기본 자동 테스트는 fixed AI 응답으로 구조·분기·오류·수정·재개·멱등성·원자 공개를 검증하며 외부 API를 호출하지 않는다. live smoke와 품질 평가 runner는 명시적 별도 실행이다. 실제 유료 호출은 이번 설계·자료 준비에서 수행하지 않았다. 모델 선택·토큰 최적화와 구체적인 비용 수용 기준은 측정 가능한 runner가 준비된 후 조정하며 구현 명세를 막는 미결정 정책으로 두지 않는다.

### 인계 조건

선행 티켓의 후보 의미·그래프 계약·단계/종료·저장/복구와 이 평가 계획을 하나의 구현 가능한 spec으로 정리한다. 단계별 입력/출력 스키마, 저장/API 계약, 실패 분류, 고정 응답 회귀 사례 및 평가 runner의 예산 설정을 구체화한다. 이후 새 구현 티켓과 blocking graph를 만든다. 검증 공백과 사후 보정 계획을 spec에 명시하고 앱 구현 완료나 품질 검증 완료로 오인하지 않도록 한다.
