## Question

기존 Topic과 연구 문서의 Issue를 같은 것으로 취급할지 별도 개념으로 둘지, 관계의 방향·출처 선택성·분석상 관계와 인간이 확정한 Supersede의 구분, 고아 노드·잘못된 참조·중복·사이클의 정책을 결정한다. 렌더링 좌표와 UI 속성은 제외한다.

## Answer

### 범위와 기본 구조

논리 그래프는 이번 입력 대화의 분석 결과다. 과거 결정 retrieval, 렌더링 좌표, AI 자동 확정·Supersede는 포함하지 않는다. 노드·관계 목록을 표현하고, 실제 대화의 모순을 나타내는 문제 표시를 함께 제공한다. 구체적인 JSON 필드명과 스키마 선언은 구현 명세에서 이 계약을 그대로 표현한다.

| 노드 | 의미 | 내용 |
| --- | --- | --- |
| Topic | 논의 주제 | 주제명·요약 |
| Issue | 주제 안에서 해결할 문제·질문 | 문제·질문 요약 |
| Decision Candidate | 같은 선택에 대한 검수 단위 | 후보 요약, 현재 대화 관측, 순서 있는 관측 이력 |
| Alternative | 검토한 선택지 | 선택지 요약, 해당 대안의 관측 결과 |
| Rationale | 대화에서 표현된 근거·배경·트레이드오프 | AI 요약 |
| Action Item | 대화에 나온 후보·결정 관련 후속 활동 | 활동 요약, 언급된 경우에만 담당자·기한 |

모든 노드는 문자열 ID와 종류 및 의미를 표현하는 요약을 갖는다. 개별 메시지 출처와 직접 인용은 필수가 아니다. 같은 이름이라는 이유로 서로 다른 선택·문제·대안을 병합하지 않는다.

### 관계

소속, 후보의 대안, 찬성·반대 근거, 후속 과제, 충돌, 의존 관계를 지원한다. 관계는 문자열 ID, 관계 종류, 시작·끝 노드 ID를 갖는다. 의미와 연결 가능한 노드 종류를 스키마·검증에 반영한다.

- 소속은 Topic/Issue 아래의 문제·검수 단위를 연결한다. Topic과 Issue는 같은 개념으로 취급하지 않는다.
- 후보의 대안은 Decision Candidate와 Alternative를 연결한다.
- 찬반 근거는 Rationale이 후보 또는 대안을 지지·반대한다는 내용을 표현한다.
- 후속 과제는 후보와 Action Item을 연결한다.
- 충돌은 입력 대화에서 확인된 양립 불가능한 선택·내용을 표현한다. 단순 동시 등장이나 이름의 유사성은 충돌 근거가 아니다.
- 의존은 한 후보 또는 Action Item이 다른 후보 또는 Action Item을 전제로 한다는 내용을 표현한다.

관계는 종류에 따른 의미 방향을 일관되게 표현한다. 충돌은 대칭 의미이며 역방향 관계를 중복 생성해 별개의 충돌처럼 세지 않는다. 관계 라벨의 영문명이나 저장상 방향 정규화는 이 의미를 유지하는 구현 명세의 기계적 선택이다.

### 후보·대안 관측과 이력

후보의 대화 관측은 제안·합의·철회·불명확을 구별하고 인간 검수 상태와 분리한다. 대안의 관측도 별도다. 한 대안이 채택되었다고 다른 대안의 거절·철회를 추정하지 않는다. 명시되지 않은 결과는 미기록으로 남긴다.

제안·합의·철회 흐름은 후보 안의 순서 있는 AI 요약 이력으로 표현한다. 별도의 이벤트 노드 종류는 추가하지 않는다. 순서를 보존하되 실제 발화 시각이 없으면 시각을 생성하지 않는다. 마지막 발화라는 이유만으로 합의가 성립했다고 단정하지 않는다.

### 누락과 맥락

근거·후속 과제가 언급되지 않으면 해당 노드를 만들지 않는다. 후보의 근거 미언급 상태를 누락된 Rationale과 구별 가능한 의미로 전달하며 가짜 근거 노드·내용을 추가하지 않는다. 담당자·기한·발화 시각 등 언급되지 않은 정보도 비워둔다.

문제 보고·질문·정보 공유만 있는 경우 검수 후보가 없어도 맥락을 보존할 수 있다. 이러한 Topic/Issue를 고아 오류로 간주하지 않는다. 근거와 후보의 연결이 깨진 경우 등 구조 오류와 정상적인 미해결 맥락을 구별한다.

### ID와 정합성

BE가 노드·관계의 문자열 ID를 발급한다. AI 단계 내 요소 연결에 필요한 임시 참조와 최종 ID의 매핑, 재시도·재분석에서 ID가 유지되는 범위는 후속 워크플로우·저장 계약에서 정한다.

중복 ID, 존재하지 않는 노드 참조, 허용되지 않은 노드 종류 연결은 구조 오류다. 제출 전에 보정 대상으로 돌리고 조용히 삭제하거나 유효한 그래프처럼 저장하지 않는다. 보정 횟수·부분 성공·최종 실패의 처리 방식은 워크플로우 티켓에서 결정한다.

실제 대화에 있는 상충 합의·철회·순환 의존은 구조 오류와 다르다. 문제 표시와 관련 요소를 보존해 인간이 검수하도록 한다. AI가 임의로 한쪽을 지워 해결하지 않는다. 모든 관계를 DAG로 강제하지 않으며, 의미상 순환을 지우는 방식으로 구조 검증을 통과시키지 않는다.

### 다음 결정으로 넘기는 내용

추출·관계 생성·검증 단계의 구성, 수정 예산·종료 및 실패 처리는 워크플로우 티켓에서 결정한다. 논리 그래프와 기존 Decision aggregate의 저장·버전·검수 이후 유효성 및 API 전달은 저장 경계 티켓에서 결정한다. 이 해결은 앱 구현 완료를 뜻하지 않는다.
