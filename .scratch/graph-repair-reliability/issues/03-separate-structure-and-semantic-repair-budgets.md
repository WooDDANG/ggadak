# 03: 구조 복구와 의미 검증 복구 예산 분리

**What to build:** 초반 구조 오류를 고치느라 유일한 repair 기회를 소진한 뒤 이어지는 의미 재검증 실패로 Analysis Request가 즉시 422 터미널 실패로 종료되지 않도록, 구조 복구와 의미 검증 복구 예산을 분리하고 전체 세션 시간·호출 예산 안에서 안전하게 제한한다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 구조 검증(check/recheck) 실패로 인한 repair와 의미 검증(verify/reverify) 실패로 인한 repair가 각각 독립된 상한을 갖는다.
- [ ] 분리된 복구 예산이 실행되더라도 세션 전체 논리 호출 상한과 세션 시간 예산을 초과하지 않도록 강제한다.
- [ ] 구조 복구 1회 후 의미 검증에서 1회 추가 복구를 거쳐 정상 완료되는 시나리오와, 두 예산을 모두 소진했을 때 터미널 실패로 마감되는 시나리오를 테스트로 검증한다.
- [ ] 중단 후 체크포인트 복원 시 누적 복구 횟수와 단계 전이가 일관되게 유지된다.
