# 구현 검증 — 2026-10-24

## Sync Job 수령

실제 서버 모듈을 먼저 불러오는 새 Node 프로세스에서 `Cannot read properties of undefined (reading 'syncJob')`를 재현했다. 기존 테스트는 reflect-metadata를 사전에 초기화하지만 실행 서버의 일부 서비스는 초기화보다 먼저 평가되어 생성자 metadata가 없었다.

서버 진입점과 loader에서 metadata를 먼저 초기화하고 Sync Job 서비스·Controller를 해당 앱의 Repository로 명시적으로 조립한다. 새 프로세스의 실제 HTTP 테스트는 비동기 전달 모드에서 빈 claim의 정상 응답, 서비스 인증, 두 worker의 동일 작업 중복 수령 방지를 확인한다. 기존 임대 복구·진행 저장 테스트도 유지했다.

## 검수 화면과 깜빡임

- App의 전체 결정·대기/보류 전수 조회를 제거했다. Review Queue는 한 상태의 현재 20건 페이지만 조회한다.
- 교체 대상은 사용자가 선택기를 열 때 CONFIRMED 기록을 페이지별로 읽는다. 다른 페이지로 이동해도 선택한 predecessor 버전 snapshot을 유지한다.
- 확정·반려·교체 이력도 명시적으로 열 때 상태별로 페이지 조회한다. 검수 큐가 비어도 이력을 열 수 있다.
- 비활성 화면에서는 검수·이력 폴링을 하지 않는다. 평상시 갱신은 30초이며 검수 직후 관련 목록·집계·열린 선택기는 즉시 무효화해 갱신한다. 충돌은 재조회 후 선택을 초기화하며 자동 재제출하지 않는다.
- 백그라운드 세션 확인은 화면을 loading으로 바꾸거나 유효한 토큰을 먼저 지우지 않는다. 같은 사용자 확인 성공 때 전체 캐시를 지우지 않아 DOM·입력 상태가 유지된다. 최초 로그인·다른 사용자 전환·만료·로그아웃·세션 복원 장애의 보호 동작은 유지한다. 세션 기간은 고정 7일이다.
- 기존 App이 기본 dashboard 탭에 Dashboard를 렌더링하지 않던 부분도 연결했다. 가벼운 집계로 배지를 표시하며 전체 결정 조회로 집계를 만들지 않는다.

브라우저 회귀 검증은 dashboard에서 검수/전체 기록 요청 0회, 열린 상태의 현재 페이지 조회, 대기/보류 전환, 교체/이력 지연 조회, 선택한 버전으로 검수, 화면 이동 후 폴링 중단, 서버 전환의 페이지·캐시 격리를 확인한다. 이 상호작용 fixture에서 목록 요청은 queue 5회·기록 5회, 목록 응답 합계 130370바이트였다. 가속된 테스트 타이머를 사용한 값이므로 운영 요청률이나 기존 대비 성능 비율로 해석하지 않는다.

## 실제 AGY 측정

합성 대화 요청 2개·각 2개 세션, 모델 gemini-3.8-flash-low, N=1·2·4, 각 1회, 호출 예산 64·토큰 예산 200000·출력 상한 8192·최대 600000ms로 실행했다. 실제 provider 호출은 14회, 보고된 토큰은 197375였다. JSON 요약은 이 디렉터리의 agy-live-results.json에 보관했다.

| N | 완료 세션 | 요청 완료 p95 | 관찰된 처리량 | 제한 |
| --- | --- | --- | --- | --- |
| 1 | 4/4 | 172.04초 | 1.39 세션/분 | 서비스 probe 실패, 자원 한도 초과 |
| 2 | 2/4 | 52.22초 | 2.30 세션/분 | 토큰 예약 예산 초과로 일부 미완료, probe 실패, 자원 한도 초과 |
| 4 | 0/4 | 없음 | 비교 불가 | 공급자 호출 전에 예산 차단 |

N=2 값은 부분 성공 요청의 관찰값이며 N=1 대비 속도 향상 근거가 아니다. N=4 미완료는 AGY의 4개 병렬 실행 불가를 뜻하지 않는다. DB 읽기 p95는 각각 약 0.34/0.42ms였지만 서비스 주소가 응답하지 않아 로그인/조회 지연은 검증하지 못했다. 표본 최대 프로세스 트리 RSS는 N=1 약 1746MiB, N=2 약 2868MiB로 초기 기준 1024MiB를 넘었다. 따라서 suggestedN과 productionRecommendation은 모두 null이다.

이 실행에서 발견한 낭비를 방지하도록 live benchmark는 provider 호출 전에 서비스 probe 성공을 요구한다. 사전 검사 실패 시 AGY를 호출하지 않는 회귀 테스트가 통과했다. 기존 운영 동시성은 변경하지 않았다. 추가 측정 예산과 실행 중인 BE가 확보될 때까지 티켓 03은 needs-info로 남긴다.
