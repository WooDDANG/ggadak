# Sync Job 복구와 검수 화면 조회·깜빡임 개선

2026-10-24 사용자가 세 티켓 초안에 `$implement`를 요청했고, 백그라운드 세션 확인 중 화면이 사라지는 문제의 구현과 티켓 추가를 요청했다.

## 범위

1. 실제 Bot의 Sync Job claim에서 발생하는 Prisma 의존성 누락을 재현·수정한다. 비동기 전달 모드와 실제 Controller 생성 경로를 포함하고 claim·진행 저장·재시작·동시 수령·서비스 인증을 보존한다.
2. Review Queue는 현재 상태·페이지를 조회한다. 교체할 확정 결정과 검수 이력은 열었을 때 페이지별로 조회한다. 비활성 화면에서는 전체 목록을 폴링하지 않는다. 검수 후 목록·집계를 갱신하고 stale version의 자동 재제출 없이 최신 후보를 확인하게 한다.
3. 기존 벤치마크로 동일 합성 대화·AGY 모델에서 N=1·2·4를 비교한다. 호출 64회·애플리케이션 토큰 예산 200000·출력 상한 8192·실행 600000ms를 초기 예산으로 사용한다. 성능 결과와 실패를 기록하며 계정·머신 전체의 보편 상한을 단정하거나 운영 환경설정을 자동 변경하지 않는다.
4. 이미 로그인된 사용자의 세션 확인은 화면을 loading 상태로 내리지 않고 수행한다. 같은 사용자·서버를 복원할 때 캐시와 입력 상태를 보존한다. 최초 로그인·로그아웃·실제 세션 만료·다른 사용자 전환은 기존 보호 동작을 유지한다. 기간 변경은 이번 범위에 포함하지 않으며 고정 7일을 유지한다.

## 검증

- 공개 HTTP claim 경로와 비동기 전달 모드를 포함한 격리 DB 회귀 검증.
- 실제 브라우저에서 검수 페이지별 조회, 교체 선택기 지연 조회, 화면 전환 후 폴링 중단, 검수 후 갱신과 세션 확인 중 DOM·입력 상태 보존 확인.
- 기존 소유권 fencing·검수 버전 충돌·인증 경계 유지.
- 타입 검사, 변경 파일 lint/format, 마지막 전체 테스트 및 Standards/Spec 별도 리뷰.
- 외부 AI 실패도 측정 결과로 남긴다. 비교 가능한 성공 표본이 없으면 권장 N을 제시하지 않는다.
