# Agentic 분석 구현 티켓 분할안

Status: needs-triage

원본 spec은 변경하지 않는다. 아래는 분할 승인 전 초안이며 승인 후 개별 issues로 게시한다. FE 변경·운영 DB 적용·유료 AI 실행은 포함하지 않는다. Bot 시작/초대 자동 스캔 제거는 이미 적용되어 별도 구현 티켓으로 반복하지 않는다.

## 제안하는 분할

1. **검증된 후보·논리 그래프의 분석부터 조회까지 연결** — 선행 없음. 단일 세션의 정상 추출·항상 의미 검증·원자 저장·guild 인증 그래프 조회를 실제 API에서 확인한다. 오류는 보정 없이 실패로 남긴다.
2. **오류 결과의 한 번 수정과 실행 예산 적용** — 선행: 검증된 후보·논리 그래프의 분석부터 조회까지 연결. 구조/의미 오류의 공유 수정 예산·재검증·최대 호출·시간 제한과 실패 상태 조회를 완성한다.
3. **재시작 복구와 다중 세션의 원자 공개** — 선행: 오류 결과의 한 번 수정과 실행 예산 적용. 단계 저장·같은 요청 재개·예산 유지·owner fencing·모든 세션 성공 후 공개를 완성한다.
4. **검수·편집 이후 그래프 snapshot과 카드 이력 연결** — 선행: 검증된 후보·논리 그래프의 분석부터 조회까지 연결. 실제 카드의 검수/편집/교체 뒤 AI snapshot과 현재 버전을 구별하고 여러 분석 이력을 조회한다.
5. **Bot 전달 복구와 terminal 재분석 구분** — 선행: 재시작 복구와 다중 세션의 원자 공개. 통신 재시도와 영구 실패를 구별하고 명시적 새 재분석·실패 보존·스캔 acknowledgement를 연결한다.
6. **사람이 검수하는 서비스 평가 정답 준비 도구** — 선행 없음. AMI 기반 gold와 추가 서비스 gold를 구별하고 후보/관계 의미 대응·정답 검수·버전/분할 검사를 오프라인에서 검증한다. 실제 한국어 gold 완료를 도구 구현의 조건으로 두지 않는다.
7. **AMI 비교 평가와 명시적 live smoke 도구** — 선행: 재시작 복구와 다중 세션의 원자 공개, 사람이 검수하는 서비스 평가 정답 준비 도구. 같은 대화를 baseline/new workflow에 입력해 검수된 의미 대응과 usage로 보고서를 생성하며 유료 실행 예산·실패·한국어 검증 공백을 표시한다. 기본 테스트는 fixture 모드다.

## Blocking 원칙

공통 파일을 만질 가능성만으로 blocking을 추가하지 않는다. 검수 이후 snapshot 확인은 정상 저장/조회가 있으면 진행할 수 있어 재시작 복구를 기다리지 않는다. gold 도구는 모델 연결 없이 구현 가능하다. 최종 평가 runner는 다중 세션 완료 결과와 gold 의미 대응 계약이 필요하므로 두 작업을 기다린다.

## 확인할 사항

- 이 크기가 적절한가, 너무 크거나 작은 티켓이 있는가?
- 선행 조건이 실제 필요한 연결만 포함하는가?
- 합치거나 더 나눌 작업이 있는가?

승인 후 기존 AI draft의 공급자 경계/구조화 출력/오류/연결/평가 작업을 이 7개에 흡수한다. 기존 인용 필수 검증 초안은 실행하지 않는다.
