# Discord login and server authorization

Configure `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI` and `AUTH_SECRET` (at least 32 random characters, identical across BE replicas). The redirect URI is a single server-configured allowlisted value and must exactly match the Discord Developer Portal OAuth redirect registration and the FE callback URL, for example `http://localhost:5173/`. HTTPS is required in production (`NODE_ENV=production` marks the state cookie Secure). Request only `identify guilds`; user.email is null because email is not requested.

FE and BE must be on the same site for the SameSite=Lax browser state cookie: use the Vite /api proxy locally or a same-origin /api reverse proxy in production. Alternatively `VITE_API_ORIGIN` supports a same-site BE hostname with `CORS_ORIGINS` set to the exact FE origin. Set CORS_ORIGINS explicitly in deployed environments. A cross-site FE/BE deployment requires an intentional cookie-policy change; it is not enabled by this flow.

1. GET `/api/v1/auth/authorize` sets a HttpOnly browser state cookie and returns Discord's authorization URL.
2. Discord redirects to FE with code and state; POST `/api/v1/auth/login` sends both with cookie credentials. State must match the browser-bound signature, expiry and unconsumed database nonce. It is consumed before code exchange; failed login restarts at authorize. The redirect URI cannot be overridden by a browser.
3. Login returns `{accessToken,tokenType:'Bearer',expiresAt,user:{id,name,email,avatarUrl,discordUserId}}`. FE keeps the token in memory, loads `/auth/guilds`, then includes `guildId` as a query parameter on every guild-scoped endpoint. Browser reload requires login again.
4. JWT uses HS256 and validates signature, issuer, audience, expiry, algorithm and persisted session. It expires in 15 minutes. A session lasts at most seven days. FE POSTs `/auth/refresh` every 10 minutes while its JWT is valid, which refreshes the Discord credential and replaces the user's memberships from Discord. Expired JWTs require login. Membership authority is bounded to 15 minutes; refresh failures do not grant stale membership indefinitely.
5. POST `/auth/logout` deletes the current persisted session. The JWT is immediately invalid. Discord refresh credentials are AES-256-GCM encrypted under a key derived from AUTH_SECRET and never returned to clients. Secret rotation invalidates existing JWTs and refresh decryption; users log in again.

`@Security('jwt')` supplies `request.user` as `{userId,sessionId}`. `AuthService.requireGuild(principal,guildId,manage=false)` is mandatory before server queries; `manage=true` additionally requires guild owner or MANAGE_GUILD. `requireDecision(principal,id,guildId?)` verifies the stored Decision guild and optional selected-guild match before direct-ID reads or writes. TSOA controllers and security resolution use app-local services, so distinct servers cannot share authorization state or repositories. Successor endpoints must use these methods; bearer verification alone does not authorize a guild.

Migration `202610120004_discord_auth` is additive. It creates User/Guild/Membership/AuthSession/OAuthState, seeds historical Guild IDs and does not alter Decision records or grant historical memberships. Generate the Prisma client and apply migrations only to an explicitly selected/backed-up DB. No production database was migrated during ticket implementation. See [ERD](../../docs/diagrams/v1-data-model.md).

The Bot uses `BOT_SERVICE_TOKEN` as a bearer token for internal monitoring, discussion analysis, and candidate-history endpoints. The FE no longer fetches global legacy feedback; server-scoped feedback remains pending. Reviews still use legacy compatibility until ticket 07 switches them.

Public HTTP test helpers: `test-support/auth.ts` provides `fakeAuthOptions()` with an injectable fake Discord adapter and `loginAsTestUser(baseUrl)` obtains a real application JWT through authorize/login. Tests use disposable DBs, never real Discord credentials.

Verified official sources (2026-10-12): [Discord OAuth2](https://docs.discord.com/developers/topics/oauth2) specifies form-encoded code/refresh exchanges, redirect URI, identify/guilds scopes and request-bound state; [Discord User Resource](https://docs.discord.com/developers/resources/user) specifies current-user and user-guild endpoints. HTTP adapter uses API v10.
